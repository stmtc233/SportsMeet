# 编排页

前端 `src/features/arrange/`,规则在 Go `internal/arrange/` 与 `internal/service/`。层级与锁定口径见 [domain.md](domain.md)。

## 页面

- 一个项目一页,标题旁可切到同一赛事的其他项目;左栏是本项目报名者名单(窄窗口收为侧面板),右侧是各轮次的组卡片。
- 多轮次项目在工具栏切换轮次,名单显示当前轮次里未分组的人。
- **拖放排位**:名单拖到位置,或点选后点「放到这里」;拖到有人的位置即互换(从名单拖来则原来的人回到名单),拖回名单即移出。径赛每组固定显示全部道次,田赛顺序始终连续(1…n)。组卡片「⋯」里编辑名称与计划时间、上移 / 下移、解锁位置、删除。
- 名单底部「从赛事添加」直接报名(可多选);取消报名与报名成绩在「报名」页;**报名立即生效,不进草稿**,之后把最新数据合并进草稿,未保存的排位改动保留。

## 本地草稿,一次保存

- 所有排位改动进不可变草稿 `ArrangeDraft`,配合撤销 / 重做(上限 100 步):`Ctrl/Cmd+Z` 撤销,`Ctrl/Cmd+Shift+Z` 与 `Ctrl+Y` 重做,`Ctrl/Cmd+S` 保存,`Esc` 取消点选。
- 有未保存改动时离开页面先确认。
- 工具栏右对齐,「放弃」常驻(无改动时置灰),改动计数放在操作最左,改动前后按钮不移位。
- **保存只提交改过的组**:每个已有组带载入时的指纹 `base`(序号、名称、计划时间、位置;由 Go `arrange.Fingerprint` 计算,前端当不透明字符串比对),连同新增组、显式删除列表与本轮次全部组的显示顺序 `order` 一起提交;没提到的组只可能被改序号,或被移走已排到别组的人。
- 草稿是 `src/features/arrange/draft.ts` 里的纯函数(有 `bun test` 单测),只负责在位置间移动人;分组排道、序号、锁定判定都在 Go。
- **数据变化即合并**:MCP 在编排页打开期间也可能写入。service 广播变更后,草稿逐组对比 `base`:被改过的组换成最新内容(丢弃本地对它的改动),其余改动保留;丢弃了本地改动就提示「有组已在别处修改」。保存时指纹不符同样重新载入并合并,不弹冲突对话框。
- 组序号由 Go 在保存时按 `order` 派生(`arrange.DeriveOrdinals`):「原序号仍递增就保留,否则取前一个 + 1」,尽量少改。
- 合并后撤销 / 重做历史清空:历史里的草稿带着旧指纹,撤销回去会把别处的改动盖掉。

## 自动编排

- **只排未分组的人、只追加新组**,已有组不动。
- 选项:每组人数、排列顺序(按报名成绩 / 随机)、位置分配(径赛「好成绩排中间道」/ 依次 / 随机,田赛依次 / 随机)、同单位分散、均衡人数。按成绩时蛇形发牌,各组强弱相当;没有报名成绩的排最后。
- 上一轮有晋级规则时,人员可选「上一轮晋级者」:取上一轮带 `Q` / `q` 的人,以上一轮成绩为种子;上一轮没录完即拒绝。
- 由 Go `arrange` 计算方案,原样追加进草稿,保存前可随意再改。随机由前端生成 `seed` 传给 Go,同一 `seed` 结果相同,便于复现与测试。
- 批量排时间(按首组时间与间隔填计划时间)待实现;目前逐组编辑。

## 已比赛的组

- 有成绩的组默认锁定:里面的人可以拖出来排进下一轮次的组,但仍留在原组;要从原组移出或改位置,须先「⋯ → 解锁位置…」。解锁后换位置,成绩跟着人走;移出的人成绩在保存时删除,该组名次重算。
- **全部重置**:「⋯ → 全部重置…」弹窗列出将删除的组与成绩数,必须输入项目名称才进入重置草稿;保存按钮变成红色「重置并保存」(`StConfirmButton`)。这是唯一能一次删掉已比赛组的入口。
