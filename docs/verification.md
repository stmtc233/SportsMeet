# 验证范围

## 自动验证

```sh
go test ./...
go test -race ./internal/service ./internal/mcp
CGO_ENABLED=0 go test ./...
go vet ./...
bunx mygo vet .
bun run test:web
bun run typecheck
scripts/check-design-system.sh
bun run test:ui
bunx mygo build -skip-dmg -skip-notarize -skip-installer
```

页面测试先安装浏览器:

```sh
bunx playwright install chromium
```

也可指定本机浏览器可执行文件,例如 macOS Chrome:

```sh
SPORTSMEET_BROWSER_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' bun run test:ui
```

- 真实 SQLite 的流程测试覆盖建赛事、表格运动员导入与报名、预赛自动编排、成绩录入与排名晋级、决赛生成、秩序册 / 成绩册 HTML、完整赛事导出与再导入。比较往返后的逐次记录、名次与 Q / q。
- MCP 使用官方 SDK 客户端连接真实本机 HTTP 监听,验证查询、单条写入、报名、编排、成绩写入、删除预览确认,兼容初始化协议。错误路径覆盖空令牌 / 错令牌、非本机 Origin / Host、2MB 请求体上限、旧令牌失效、端口占用、启停与重启恢复。
- service 回归测试覆盖过期确认、并发重复确认、已比赛数据的删除保护、成绩覆盖与空成绩直接写、田赛逐次记录、整批失败不写入、完整成绩日志、文件与目标数据变化使导入预览失效、MCP 性别混放拒绝、接力队伍与棒次导入、设置持久化与令牌不入日志。

- 页面冒烟共 14 项:1280 / 800 × 浅色 / 深色的核心页面检查,以及设置保存、输入与焦点跨宽窄切换保留、离开确认、服务状态与保存失败反馈;批量排时检查 1280 / 800 的预览、保存刷新、草稿阻止操作、参数修改与外部数据变化使预览失效、过期提交和校验错误反馈。接力测试检查队伍与棒次新增 / 调序、按队报名、自动编排保存后临时组消除、计时输入与保存、已有成绩时禁改棒次、保存失败保留输入,并覆盖连续选择时退出菜单不拦截点击。桥接桩模拟原生无返回值为 `null`,业务数据使用确定性样例;数据库与系统对话框由其他验证覆盖。

- 本机 macOS arm64 可生成 `build/darwin-arm64/SportsMeet.app`,该打包验证跳过磁盘映像、公证与安装包。

## 桌面实测

macOS WebView 使用独立的 QA 应用名称与数据目录,验证:

- 新建赛事的原生 `<dialog>`、保存与列表刷新。
- 原生文件选择、示例交换格式文件导入预览、确认写入与项目进度刷新。
- 秩序册 / 成绩册预览、独立打印窗口与系统打印对话框;取消打印可返回主窗口。
- 设置分类与 MCP 开关,实际本机监听的开启 / 关闭、状态和地址回显、操作成功反馈。
- 暗色显示与平滑圆角的实际呈现。
- 打包后的独立 QA 应用验证「编排 → ⋯ → 批量排时间…」:真实 Go / SQLite 预览原时间与新时间,跳过已有 DNS 的组,保存后组卡片自动刷新且已比赛组时间保留。

测试应用的 MCP 结束时关闭。日常应用的数据目录不用于测试。

## 仍需人工验证

- 接力在原生 WebView 中的完整现场连续操作;浏览器与真实 Go / SQLite 已分别验证。
- 完整现场流程连续操作,尤其是运动员手动拖放、田赛逐次录入的键盘操作、800 宽原生窗口与显式外观切换。
- 不同打印机、纸张与实际纸张分页。
- Windows / Linux 的 WebView、文件对话框、打印、打包与安装。
