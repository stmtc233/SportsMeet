# 编排页

前端 `src/features/arrange/`,规则在 Go `internal/arrange/` 与 `internal/service/`。层级与锁定口径见 [domain.md](domain.md)。

## 页面

- 队伍项目的名单与位置表示队伍,与个人项目共用草稿移动、保存、排道、计划时间和晋级逻辑;「管理队伍」可编辑队名、单位和成员并报名。队伍规则见 [domain.md](domain.md)「队伍与接力」。
- 一个项目一页,标题旁可切到同一赛事的其他项目;左栏是本项目报名者名单(窄窗口收为侧面板),右侧是各轮次的组卡片。
- 多轮次项目在工具栏切换轮次,名单显示当前轮次里未分组的人。
- **轮次开始时间**:工具栏轮次切换旁的时钟按钮显示当前轮次的开始时间(未设置时为「开始时间」),点开 `RoundStartDialog` 填日期与时间,时间留空即清除。它立即写入(`Arrange.setRoundStart`),不进草稿;因为不改任何组、不进组指纹,有未保存的排位改动时也可以设置,刷新后本地草稿里没有单独时间的组(含未保存的新组)跟着显示新的开始时间。对话框在保存前显示 service 给出的「时间不在赛事日期内」提示,不拦截。
- **组的时间显示**:组卡片与成绩页标题里,单独指定的时间用 `StTag`;沿用轮次的时间用次要文字(`HeatTime`,悬停提示「沿用轮次开始时间」),不像单独指定;有预计用时时卡片另显示「N 分钟」。
- **冲突标记**:组卡片标题上有「冲突 N」标签(`ConflictTag`)时,悬停列出每位运动员、冲突类型与另一组(时间、项目、轮次、组)。标签按草稿计算,未保存的时间、预计用时与位置改动都算:草稿变化或赛事数据变化后停顿 300ms 合并为一次 `Arrange.draftConflicts` 调用(`useDraftConflicts`)。只提示,不拦截保存。规则见下文「冲突检查」。
- **拖放排位**:名单拖到位置,或点选后点「放到这里」;拖到有人的位置即互换(从名单拖来则原来的人回到名单),拖回名单即移出。分道与分道后抢道项目每组固定显示全部起跑道次，不分道项目和田赛顺序始终连续(1…n)。组卡片「⋯」里「编辑组…」(名称、单独的计划时间与预计用时)、上移 / 下移、解锁位置、删除。「编辑组」时间留空即沿用轮次,此时对话框显示「沿用轮次 HH:mm」;预计用时可不填,确定时经 `Arrange.heatPlan` 由 Go 校验(1–1440 分钟)并返回显示文本,不通过就留在对话框;计划时间不在赛事日期内时显示提示,不拦截。
- 名单底部「从赛事添加」直接报名(可多选);取消报名与报名成绩在「报名」页;**报名立即生效,不进草稿**,之后把最新数据合并进草稿,未保存的排位改动保留。

## 本地草稿,一次保存

- 排位、组名、逐组计划时间与预计用时改动进不可变草稿 `ArrangeDraft`,配合撤销 / 重做(上限 100 步):`Ctrl/Cmd+Z` 撤销,`Ctrl/Cmd+Shift+Z` 与 `Ctrl+Y` 重做,`Ctrl/Cmd+S` 保存,`Esc` 取消点选。
- 有未保存改动时离开页面先确认。
- 保存期间禁止继续编辑;绑定在写入后返回 service 重新读取的项目详情,界面以该快照确认草稿已保存,清除临时新增组、重置标记和历史。期间到达的数据事件暂缓合并,避免新增组同时保留临时键与数据库 ID;其他外部变更仍按下述指纹合并。保存失败保留草稿并重新读取以合并外部变化。
- 工具栏右对齐,「放弃」常驻(无改动时置灰),改动计数放在操作最左,改动前后按钮不移位。
- **保存只提交改过的组**:每个已有组带载入时的指纹 `base`(序号、名称、单独的计划时间、预计用时、位置;不含实际开赛时间;由 Go `arrange.Fingerprint` 计算,前端当不透明字符串比对),连同新增组、显式删除列表与本轮次全部组的显示顺序 `order` 一起提交;没提到的组只可能被改序号,或被移走已排到别组的人。
- 草稿是 `src/features/arrange/draft.ts` 里的纯函数(有 `bun test` 单测),只负责在位置间移动人;分组排道、序号、锁定判定都在 Go。
- **数据变化即合并**:MCP 在编排页打开期间也可能写入。service 广播变更后,草稿逐组对比 `base`:被改过的组换成最新内容(丢弃本地对它的改动),其余改动保留;丢弃了本地改动就提示「有组已在别处修改」。轮次开始时间不在组指纹里:它变化时轮次信息取最新,保留下来的本地组没有单独时间就改显示新的开始时间,单独时间未改的取最新文本。保存时指纹不符同样重新载入并合并,不弹冲突对话框。
- 组序号由 Go 在保存时按 `order` 派生(`arrange.DeriveOrdinals`):「原序号仍递增就保留,否则取前一个 + 1」,尽量少改。
- 外部修改使项目在道次与顺序之间切换，或修改有道次项目的道数时，以最新数据重新建立草稿；存在本地改动则提示「项目配置已修改」，避免草稿位置在新配置下隐藏。
- 合并后撤销 / 重做历史清空:历史里的草稿带着旧指纹,撤销回去会把别处的改动盖掉。

## 自动编排

- 全能分项的名单由全能统一报名提供，分项页不能单独添加或取消报名；排位和成绩仍使用本页。
- **只排未分组的人、只追加新组**,已有组不动。
- 选项:每组人数、排列顺序(按报名成绩 / 随机)、位置分配(分道与分道后抢道「好成绩排中间道」/ 依次 / 随机，不分道与田赛依次 / 随机)、同单位分散、均衡人数。按成绩时蛇形发牌,各组强弱相当;没有报名成绩的排最后。
- 起跑方式与容量使用已保存的项目配置：分道与分道后抢道每组人数不得超过道数，不分道项目只按每组人数分组，位置为顺序；按报名成绩时所有计时项目均以用时少者优先。界面默认每组人数为道数或无道次项目的 12 人，可自行调整。
- 上一轮有晋级规则时,人员可选「上一轮晋级者」:取上一轮带 `Q` / `q` 的人,以上一轮成绩为种子;上一轮没录完即拒绝。
- 由 Go `arrange` 计算方案,原样追加进草稿,保存前可随意再改。随机由前端生成 `seed` 传给 Go,同一 `seed` 结果相同,便于复现与测试。

- 分组选择在 `deal.go`：每行用双向可用组链表保持蛇形方向；高频单位用最小值树选同单位人数最少的组，低频单位扫描到第一个零计数候选。阈值为总人数平方根，同计数按当前蛇形方向选组；单项目最坏工作量约 `O(n√n log h)`（h 为组数），不逐人完整扫描所有组。与直接扫描规则的 560 种组合逐组比对，保持相同输入与 seed 的完整输出。

## 批量排时间

- 编排页当前轮次的工具栏「⋯ → 批量排时间…」打开对话框;输入首组日期、首组时间与间隔,先「预览」,再「保存」。默认日期取首个未比赛组的生效计划时间(单独时间或沿用的轮次开始时间)的日期,否则为项目显示的日子(`EventDetail.day`),时间取该组生效时间或 09:00,间隔默认取该组预计用时,没有则 5 分钟。
- 「日程」页工具栏「连排…」打开同一对话框的多轮次形态(`ScheduleDialog` 的 `multi`):按日程页的顺序列出赛事全部轮次(未安排时间的在后),勾选要连排的轮次,另填「轮次间隔」(0–1440 分钟,默认 0)。勾选的轮次按勾选先后追加到「连排顺序」列表,选了两个以上时可用每行的上移 / 下移按钮(可键盘操作)调整先后,调整即清除预览;请求的 `rounds` 就是这个顺序,service 按它排。没有勾选时「预览」置灰。默认日期与时间取列表里第一个有未比赛组的轮次,否则为赛事第一天的 09:00。
- 编排页入口立即写入已保存的组,不进入排位草稿;存在任意未保存编排改动、正在保存或当前轮次没有已保存的组时入口置灰。有草稿时提示「请先保存编排」。这样可以避免批量时间写入后,草稿里同一组的排位或名称被合并覆盖。日程页连排写入后,打开中的编排页按「数据变化即合并」处理。
- service `schedule.go` 的 `PreviewSchedule` / `ApplySchedule` 同时供界面绑定与 MCP 使用,单个轮次是多轮次的特例(`ScheduleRequest` 不填 `rounds` 时只排 `eventId` / `roundId`),只有一套计算。前端 `ScheduleDialog` 经 `scheduleController.ts` 调用,不计算时间。预览列出实际变化的「原安排 → 新安排」(时间与预计用时;多轮次另有「轮次」列)、跳过的组、排完后的时间冲突与提示(`warnings`,如「N 组不在赛事日期内」「排完后有 N 处时间冲突」,只提示不拦截);修改任一参数或勾选、接收数据变化后清除预览。
- 轮次按请求里 `rounds` 的先后处理,不按项目列表或已有时间重排;顺序不同即不同的计划,指纹也不同。每个轮次按组序号从小到大处理。首个未比赛的组使用首组时间,之后每个未比赛的组递增间隔;有成绩的组由 `HeatFacts.KeepReason` 判定并跳过,不占间隔。间隔同时是每个被排组的预计用时。连排时下一个轮次的首个未比赛组排在上一组开始后一个间隔(即上一组预计结束时)再加轮次间隔;某个轮次没有未比赛的组就不占时间,也不加轮次间隔。未比赛组已有的计划时间与预计用时参与重新安排,两者都与目标相同的行不列入改动;沿用轮次的组写入单独时间,原安排显示沿用的时间并标「（沿用轮次）」。
- 首组时间必须是有效的本地 `YYYY-MM-DDTHH:mm`,年份 1–9999,间隔为 1–1440 分钟的整数,轮次间隔为 0–1440 分钟的整数。按本地年月日时分运算,支持跨午夜、跨年与闰日,不转换时区或按夏令时跳时;超出日期范围时整批拒绝。连排的轮次须属于同一赛事、不得重复,否则拒绝。校验、运算与预览里的「原安排 / 新安排」文本都用 [domain.md](domain.md)「时间」的规则。
- **排完后的冲突**:预览把改动套到全赛事已保存的时间上再做「冲突检查」,只列出至少一方是被改组的冲突(`conflicts`),并在 `warnings` 里加「排完后有 N 处时间冲突」;不影响能否保存。
- 预览和提交均持 service 写锁读取。指纹覆盖参数、赛事(含起止日期)及每个目标轮次所属项目与轮次的完整状态,包括轮次开始时间、组序号、名称、时间、预计用时、实际开赛时间、位置与成绩;其他项目的变化只影响冲突提示,不使确认过期。提交重新计算后比对指纹,不一致返回 `E_STALE`,要求重新预览;任一错误阻止整批写入。
- 保存仅在一批事务中更新变化组的 `scheduled_at` 与 `duration_minutes`,不改轮次开始时间、组序号、位置、成绩、名次或晋级;日志动作 `heats.scheduled` 保留请求、原安排和新安排,来源分别为 `ui` / `mcp`。单个项目的变更通知与日志带该项目,跨项目连排的通知 `eventId` 为空、日志摘要为「N 个轮次」;成功广播 `heats` 后由界面重新读取。
- 空轮次、全部已比赛或时间完全相同时可预览但没有改动,界面「保存」置灰;确认提交空改动不写日志、不发通知。

## 冲突检查

- 纯函数 `arrange.Conflicts`:输入全赛事每个组的生效计划时间(单独时间,否则轮次开始时间)、预计用时与组内运动员,队伍组展开为队员,全能分项与普通项目一样参与。没有生效时间的组不参与;没有预计用时的组按时间点处理(结束 = 开始)。
- 同一运动员的两个组时间重叠(后一组开始早于前一组结束,或两组同一分钟开始)标为「时间重叠」;不重叠但前一组结束到后一组开始不足「最短休息时间」标为「间隔 N 分钟」。同一组内不和自己冲突,一人在同一组只算一次。
- 最短休息时间是设置项(「设置 → 编排 → 最短休息时间」,0 = 只查重叠,可选 5–60 分钟;service 接受 0–1440),service 读取后传入。
- 只提示,不拦截任何保存(用户要求):编排保存、组时间、轮次开始时间与批量排时都照常写入。
- 算法按运动员分组,每人的组按开始时间排序后扫描一遍,只保留结束时间加休息仍可能碰到下一组的组;工作量随每人所在组数增长,不随全赛事组数平方增长。
- service `timetable.go`:`MeetConflicts`(赛事全部冲突与所用休息时间)、`Schedule`(日程视图带冲突)、`DraftConflicts`(编排页草稿的冲突,只读)、`EditHeat` / `SetHeatTime`(改组后返回该组的冲突);都经 `loadMeetPlan` 一次读取赛事、项目、轮次与组的时间和位置、成绩存在标记、报名人数、队伍、运动员和设置，查询次数固定；批量排时间的目标项目另读完整成绩用于确认指纹，见 [storage.md](storage.md)「查询」。冲突的显示文本(「时间重叠」「间隔 N 分钟」、另一组的完整名称 `text`:带日期的时间、项目、轮次、组)由 Go 生成。
- **草稿冲突**:`DraftConflicts` 接收当前项目草稿里全部轮次的组(键、轮次、组名、单独时间、预计用时、选手;删除的组不传),用它们替换该项目已保存的组,叠加到全赛事已保存的数据上计算,按组键返回冲突。选手在队伍项目里是队伍 ID,展开为已保存的队员。草稿组以在本轮次草稿里的位置编号(「第 N 组」或组名),与组卡片一致;草稿里不合法的时间或用时按未填处理,保存时仍由编排保存校验。

## 竞赛日程

- 侧栏「日程」页(`src/features/schedule/`)读取 `Arrange.meetSchedule`:按天分段,每天按轮次的最早计划时间(轮次开始时间或任一组的单独时间)排列,同一时间按项目列表顺序。跨过午夜的轮次列在开始那天,之后的时间带日期。每个轮次显示开始时刻、项目与轮次名、组数与人数,下列各组的生效时间(沿用轮次的用次要文字)、组名、预计用时、预计结束、人数、「已有成绩」与冲突标签;已比赛的组沿用轮次开始时间时,改轮次时间仍允许,组跟着显示新时间,「已有成绩」标签照常标出。
- **未安排时间**:没有任何计划时间的轮次列在最后一段「未安排时间」,标题旁显示数量,默认折叠,点「展开」/「收起」切换(本页内记住,离开即复原)。段内已编排(有组)的轮次在前,没有组的在后,各自保持项目列表顺序。赛事有项目但都没有时间时,页面另显示「还没有安排时间」;没有项目时显示「还没有项目」。
- **人数**(`TimetableRound.people`,Go 计算):已有组的轮次是排进组的人数;项目的第一个轮次还没有组时是报名人数(`peopleEntered` 为真,页面显示「报名 N 人」);其余没有组的轮次为 0。队伍都按队员计。
- 页顶「时间冲突」列表每处一行:运动员、类型与两个组的完整名称,每个组旁有「编排」按钮跳到该项目的编排页。窄窗口(≤ 900px)下每行改为上下排列,文字换行,不截断、不靠悬停。设置了最短休息时间时标题右侧显示它。
- 轮次标题的时钟按钮改轮次开始时间(`RoundStartDialog`,`SetRoundStart`);组行的「编辑组」改名称、单独时间与预计用时(`HeatDialog`,经 `Arrange.editHeat` → service `EditHeat`)。`EditHeat` 按该组载入时的指纹提交,在写锁内复用编排保存(只改这一组,位置与成绩不变),指纹不符返回 `E_STALE`;有成绩的组也能改时间。MCP `set_heat_time` 走同一实现(`SetHeatTime`,保留组名)。两者返回新指纹、赛事日期外提示与改后该组的冲突。「编排」按钮跳到该项目的编排页。
- 日程页随赛事任意数据变化与设置变化重读,不保留本地改动。

## 已比赛的组

- 有成绩的组默认锁定:里面的人可以拖出来排进下一轮次的组,但仍留在原组;要从原组移出或改位置,须先「⋯ → 解锁位置…」。解锁后换位置,成绩跟着人走;移出的人成绩在保存时删除,该组名次重算。
- **全部重置**:「⋯ → 全部重置…」弹窗列出将删除的组与成绩数,必须输入项目名称才进入重置草稿;保存按钮变成红色「重置并保存」(`StConfirmButton`)。这是唯一能一次删掉已比赛组的入口。
