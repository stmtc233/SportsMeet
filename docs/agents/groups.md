# 赛事组别

组别实体为 `domain.CompetitionGroup`，目录读取在 `store/groups.go`，管理、归属建议、调整、分组榜单与打印在 `service/groups.go`、`group_*.go`，界面在 `src/features/groups/`。

## 实体与归属

- 组别属于赛事，以 `groupId` 引用，`name` 经 `domain.NormalizeText` 在赛事内唯一，`ordinal` 决定列表、榜单与打印的显示顺序。年级名称是组别的常见用途，名称不限于年级。
- 项目可属于一个组别，空值表示不分组别；全能及其全部分项使用同一组别。项目的 `groupLabel` 是从目录读取的显示值，数据库同名列是兼容缓存，不能作为独立可编辑组别。
- 参赛单位通过 `groupIds` 属于零个或多个组别；运动员有至多一个默认 `groupId`。运动员的 `grade` 是资料字段，不直接决定报名或计分。改默认组别保留已有报名。
- **运动员的组别跟着单位**：有单位的运动员，组别必须是单位组别之一；单位只有一个组别时就是它，单位没有组别时为未分组。规则是 `domain.FollowUnitGroups`，由 `service/group_follow.go` 接进每个写入口（单位与运动员保存、界面与 MCP 的归属调整、删除组别、表格与登记表导入、交换格式导入），与原写入同一事务：
  - 单位组别变化：运动员的组别仍在单位组别里的保留；单位只剩一个组别时全部归入它；否则改为未分组。
  - 运动员选了单位没有的组别：单位加入该组别；单位原来没有组别时，它的其他运动员随之归入。
  - 没有单位的运动员保留自己的组别。
  原因：两份归属各自修改时，单位进了组别、运动员仍在「未分组」；运动员所在组别单位没有时，组别人数算了他，树上却哪个单位下都没有他。
- 组别可创建、改名、排序和删除。改名同步自动生成的项目显示名称，手工显示名称保留，原始成绩与编排保持。删除在同一事务中把引用它的项目、全能（含分项）改为未分组、移除单位归属，运动员按上条随单位剩下的组别调整，项目改组规则同下文；改为未分组后与其他项目身份重复时拒绝删除。确认框列出受影响的项目、单位与运动员数量。
- `SaveEvent` / `SaveCombined` 接受 `groupId`；仅传 `groupLabel` 的名称调用在同一事务中按规范化名称复用或创建目录项，兼容现有 MCP 客户端。同时传 ID 与不同名称时拒绝。所有引用必须属于同一赛事。

- 沿用项目与赛制新建赛事时的定义复制与引用映射见 [domain.md](domain.md)「沿用项目与赛制新建赛事」。

## 调整

- 项目、全能、单位与运动员的组别在界面上直接修改，不需要预览：编辑对话框里的组别随时可改；项目、全能与运动员列表多选后「调整组别」菜单选一个组别（或「未分组」）立即生效，经 `ChangeGroup`（项目、全能，全能的分项一起调整）与 `AssignGroups`（单位、运动员）写入。单位可属于多个组别，归属在单位对话框里勾选，或在组别对话框里勾选它包含的单位；两个对话框在保存前写出随单位调整的人数（「32 名运动员将归入「初一」」，`GroupAssignmentFollows` 只读计算，可带一个尚未保存的组别）。运动员对话框换单位时组别按同一规则带出，单位只有一个组别时不提供「未分组」。原因：改组别只改引用与显示名称，不动报名、编排与成绩，随时可以改回；逐步预览只会拖慢整理工作。
- 调整后身份重复时整批拒绝，不合并项目。所有语句一次事务写入，记录 `group.projects` / `group.assignments` 日志并广播 `groups` 变更。
- 调整只更新组别引用与自动显示名称，不移动报名、不合并轮次、不重排位置、不改成绩、不拆分已有混年级项目。成绩排名仍在各项目内独立计算。
- MCP 经 `PreviewGroupChange → ApplyGroupChange`、`PreviewGroupAssignments → ApplyGroupAssignments` 调整：预览给出归属变化（含随单位调整的运动员与随运动员加入的组别）、`follows` 人数、各组团体总分与名次变化及跨组报名提示；指纹覆盖请求与预览内容，提交持 service 写锁重算，比对 `confirmed=true` 与指纹，预览内容变化返回 `E_STALE`。

## 报名、整理与导入

- 个人项目与全能的报名选择默认只看同组，可查看全部；已选择者不会因筛选消失。运动员明确默认组别与项目不同时显示跨组提示，仍可保存；队伍按成员逐一检查，不限制跨组参赛。
- 「整理归属」只列尚无归属的单位和运动员，没有可整理的对象时按钮置灰。建议来源为已有报名（队伍展开到成员）、年级文字与组别名称规范化后相等、单位的唯一组别；只有一个候选时预选，多个候选须用户选择。用户点「保存」才写入，不推断不同年级称呼之间的对应关系。
- 表格导入支持「参赛组别」列，按目录名称匹配；未填写且单位唯一组别时可带出。单位全称优先匹配，简称有多个候选时拒绝该行；项目名匹配结合性别与组别，仍有多个候选时拒绝，不选第一个。导入预览展示待保存资料和问题，所有业务匹配在 Go。
- 交换格式与兼容读取规则见 [交换格式](../interchange-format.md)；迁移规则见 [storage.md](storage.md)「组别数据」。

## 页面与打印

- 「报名」页左侧的树按「组别 → 参赛单位」排列，组别在树里添加、编辑（名称与所含单位）、排序与删除，整理归属也在这里；运动员名单按树上选中的组别与单位筛选。组别下列出属于它的单位，每个单位写它在该组别的运动员数；「未分组」列出没有组别的单位，以及有未分组运动员的多组别单位，每名运动员都在某个单位下出现；后者在它的各组别下标「N 人未分组」。项目、全能与运动员的组别下拉都可「新建组别…」。「项目」页（含全能）在赛事有组别时显示组别筛选，项目与全能创建带出当前筛选的组别。运动员名单与「项目」页都可多选后经「调整组别」菜单直接调整。总览的「赛事结构」按同样的分组列出单位与项目。没有组别的项目、单位与运动员在界面上统一称「未分组」。
- 筛选按赛事记忆，筛选的组别被删除后按「全部组别」显示（`useGroupFilter`），不回写记住的值。
- 团体榜与成绩册按组别分别计算与展示，单位范围、零分和并列规则见 [team-scoring.md](team-scoring.md)。打印页的组别下拉可勾选多个组别，不勾或全勾为全部组别，每组另起页；组内再按已有项目顺序与打印设置排版。
