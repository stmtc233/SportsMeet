# 团体总分

实体与规则在 `domain/team_scoring.go`，纯计分在 `scoring/team_scoring.go`，赛事规则读取在 `store/team_scoring.go`，服务在 `service/team_scoring*.go`，界面在 `features/team-scoring/`。

## 规则与归属

- 团体总分属于赛事，按参赛单位汇总；个人项目使用运动员的 `unitId`，队伍项目使用队伍的 `unitId`。队伍整队计一次，不向成员分摊；成员所属单位不改变队伍得分归属。修改运动员或队伍的单位后，得分随当前归属重新汇总。
- `TeamScoringRules` 保存 `enabled`、按名次排列的 `places`、项目并列计分方式 `tiePolicy`、接力默认倍数 `relayMultiplier` 和 `overrides`。没有规则时默认未启用，名次分值为 9、7、6、5、4、3、2、1，项目并列按占用名次分值均分，接力两倍，其余一倍。
- 名次分值与倍数为 0–9007199254740991 的整数，名次分值非递增且至少一项；该范围保证 Go 与前端绑定往返的规则值相同。倍数为 0 表示不计分。`overrides` 每条指定一个普通项目 `eventId` 或一个全能 `combinedId`，不能同时指定、不能重复，目标必须属于本赛事。
- 全能只按全能总排名计一次；全能分项不能单独设置规则或贡献团体得分。全能的成绩换算「积分」与名次换算「团体得分」分别展示。
- 与默认倍数相同的例外不写入规范化规则，例外按目标 ID 排序。已删除目标的例外在读取与导出时省去，避免引用不存在的项目；数据库中的累计总分与名次没有独立可编辑值。

## 计分与并列

- 普通项目只读决赛跨组总排名，不读组内保存的名次；其他轮次不计分。决赛至少有一名已排位的参赛者，且所有已排位者都有确认的成绩时，整项计入。空成绩或高度过程记录使整项待计分；清除已有成绩后整项撤回计分，录完再计入。轮次完成口径与现有排名一致，不要求未排进决赛的报名者录入成绩。
- 全能在全部报名者的分项均有处理结果后计入，只为有总排名资格者按总名次计分；未完成或无报名的全能待计分。原始成绩、全能资格与完成规则见 [combined.md](combined.md)。
- `DNS / DNF / DQ / NM` 没有普通项目名次，不得分。有效成绩在计分名额外得 0 分。没有参赛单位的参赛者仍占名次并参与并列均分，明细列在「无参赛单位」，分值不递补给其他参赛者。
- `tiePolicy=average`：并列者占据的所有名次分值之和除以并列人数，名额外的分值按 0 计；例如二、三名为 7、6 分，两人并列第二各得 6.5 分，下一名第四。`same`：并列者各得其名次对应的分值，下一名仍按现有项目排名顺延。基础分乘计分倍数为团体得分。
- 全部计算与排序使用 `big.Rat` 精确分数，不进行中间舍入。API 的 `ScoreValue.exact` 是整数或约分分数；`text` 为无多余零的有限小数，循环小数使用约分分数（如 `1/3`）。界面、预览与打印使用 Go 的显示值。
- 单位按精确总分降序排列，同总分直接并列同名次、下一名顺延（用户要求），没有比较各名次数量的选项。各组范围内的参赛单位均列出，未得分为 0；尚无项目计入时不列单位名次。
- 已启用且至少一个计分项目、范围内所有计分项目均已计入时显示「正式排名」，其余为「暂列排名」，显示已计分 / 应计分项目数。不计分项目不计入进度分母。

## 服务与确认

- `GetTeamScoreBoards(TeamScoreFilter)` 返回按目录顺序排列的独立榜单；`groupId` 省略为全部组别分别出榜，空字符串为未分组。每组单位范围为配置该组的单位与所选项目实际报名、排名的单位，保留零分；跨组单位显示提示。未分组范围包含无组别归属的单位及实际参赛单位。各组不合并总分；同一单位可在不同组分别出现。
- `GetTeamScores(TeamScoreFilter)` 返回规则、全部可配置目标、组别、当前范围排名、得分明细、无单位明细和计分进度。按项目的性别、组别或普通项目／全能 ID 集合筛选，先选项目再重新汇总。兼容名称调用的 `groupLabel` 省略为全赛事汇总，空字符串为无组别；界面与分组打印使用 `GetTeamScoreBoards` 及 `groupId`，未知目标 ID 拒绝查询。
- 读取走只读连接、不持 service 写锁，在固定次数的赛事批量查询上计算，不按项目或组逐个查询数据库；读取中途有写入时，变更事件使页面重新读取。规则预览持写锁。原始成绩、运动员与队伍的单位归属、项目配置、规则、全能结构和全能计分表与组别目录、单位组别归属共同决定结果。
- 界面数字输入以原文经 `SaveTeamScoring` → `ParseTeamScoringInput` 在 Go 解析，留空的项目倍数沿用默认，0 不计分；保存直接生效，规则没有变化时不写入。原因：规则只决定读取时的计算结果，不改任何原始记录，保存后页面立即显示新排名，改错可再改回。MCP 修改规则经 `PreviewTeamScoring → ApplyTeamScoring`。
- MCP 预览通过 `beforeBoards` / `afterBoards` 给出各组每个单位原、新总分与名次；`before` / `after` 保留全赛事汇总供兼容调用。指纹覆盖规范化请求、赛事资料、当前规则、全部项目／轮次／完整成绩、全能、运动员、单位及队伍；提交持同一写锁重算，比对 `previewHash` 与 `confirmed=true`，任一相关数据变化返回 `E_STALE`。单个事务保存规则，记录 `team_scoring.rules` 日志，广播赛事的 `team_scoring` 变更。失败不改原始成绩。

## 页面与打印

- 赛事侧栏「团体总分」逐组列榜：组别名后标「正式排名 / 暂列排名」，右侧「已计分 x / y 项」打开该组计分项目列表（倍数、状态，点击进入项目）。没有计分项目的组别不出榜。性别用分段控件（全部 / 男子 / 女子 / 混合），选定一个性别时只显示总分列；赛事有组别时可按组别筛选。选择与滚动位置按赛事记住。点击单位行打开得分明细，明细行进入项目成绩或全能工作区。
- 未启用时页面只有「启用团体计分」一个按钮，按当前（默认）规则直接启用。「赛事设置」的「团体总分」另有同一开关与「计分规则」入口，开关保存当前规则并只改启用状态。「计分规则」对话框编辑启用状态、名次分值、名次并列方式、接力默认倍数与各项目倍数，点「保存」直接生效；Go 校验失败时提示错误、保留输入。
- 界面经 `controller.ts` 调用生成的 `TeamScoring` 绑定，赛事任意变更重新读取，结果按完整筛选键缓存。
- 「打印 → 团体总分」单独打印总分表；「赛事设置」的「打印 → 团体总分表」默认开启，在各组成绩册项目之前附表；可选择一个或多个组别，每组另起页。未启用计分时不附表，单独打印的入口说明未启用并禁用打印。
- 按部分项目打印时只汇总所选普通项目和全能，不展开分项重复计分；表中写「所选项目」并列出计分项目名称。打印全部项目写「全部项目」。表中使用与界面相同的性别分数、总分、名次、完成状态和进度，范围、进度与状态写在标题右侧一行；所有单位混合得分都为 0 时不印「混合得分」列。复用现有 A4 预览分页及系统打印窗口。

## 数据、MCP 与交换格式

- 迁移 `0009_team_scoring.sql` 的 `meet_team_scoring(meet_id, rules_json)` 保存赛事规则，`meet_id` 为带索引的主键与级联外键；已有赛事默认未启用。删除赛事同时删除规则。
- MCP 的 `get_team_scores` 查询规则、范围排名与明细；`preview_team_scoring → apply_team_scoring` 经预览确认后写入，与界面共用规则校验。MCP 不提供直接编辑单位总分或单位名次的入口。
- 交换格式 v7／v8 在 `meet.teamScoring` 保存完整规则与文件内普通项目／全能引用，不导出计算结果。新赛事导入映射目标 ID 后保存规则；同赛事导入规则须与目标规范化规则一致，冲突整份拒绝；v1–v6 导入新赛事默认未启用，导入已有赛事保留目标规则。完整字段见 [交换格式](../interchange-format.md)。
