# 领域模型:赛事、项目、报名、成绩

术语见 [AGENTS.md](../../AGENTS.md) §2。实现在 `internal/domain/`(实体与校验)、`internal/service/`(写入口)、`internal/scoring/`(成绩)。

## 层级

```
赛事 meet
├── 参赛单位 unit
├── 运动员 athlete            ← 属于赛事,各项目共用
└── 项目 event                ← 一个单项
    ├── 队伍 team             ← 队伍项目，接力成员按棒次排列
    ├── 报名 entry            ← 运动员(接力为队伍)进入本项目
    └── 轮次 round
        └── 组 heat
            └── 位置 slot → 成绩 result
```

- **项目 = 一个单项**:必带性别(男 / 女 / 混合)与项目名 `discipline`,赛事组别引用 `groupId` 可选，`groupLabel` 为目录派生显示值。男女、不同距离必须拆成不同项目。原因:不加约束时,经 MCP 导入的报名表会把男女、50m 与 100m 混进同一项目,之后分组、排名全错。不要为省事放松这条校验,也不要让项目可以不属于赛事。
- **项目名称留空时自动组成**:「性别前缀 + `discipline` + 空格 + `groupLabel`」,如「男子100m 初中组」。组成规则只在 Go 一处实现,前端预览也调用它。
- **同一赛事、同一全能归属内 `gender + discipline + groupLabel` 不重复（普通项目归属为空）**;`discipline` 宽松比较(`100 米` = `100m`,`4x100M` = `4×100m`)。
- 项目、运动员创建时指定所属赛事,之后不可改。
- **轮次**:每个项目有一个决赛;决赛之前可以有预赛、次赛、半决赛,每个阶段至多一个轮次,各带自己的晋级规则(两个人数不为负、至少一个大于 0),序号按阶段先后(预赛 → 次赛 → 半决赛 → 决赛)。`EventInput.rounds` 列出决赛之前的轮次,留空即「直接决赛」;保存时按阶段与已有轮次对应:新出现的阶段新建,仍在的只改晋级规则并保留它的组,没列出的删除,全部轮次重新编号。已有组的轮次不能这样删掉,须先删除它的组,否则组、位置与成绩会随轮次一起消失。`EventRow.rounds` 与 `formatText`(「预赛 + 半决赛 + 决赛」、「直接决赛」)由 Go 给出。界面的「赛制」提供四种常用组合(直接决赛、预赛 + 决赛、预赛 + 半决赛 + 决赛、预赛 + 次赛 + 半决赛 + 决赛),项目已有的其他组合(经 MCP 或导入而来)照原样列出;MCP 可保存任意组合。从上一轮晋级编排、`Q` / `q`、排名与打印都按序号取上一轮,对所有阶段一致。
- 队伍与接力棒次由 `service/teams.go` 管理;报名、编排、成绩、排名晋级与导入导出均按队处理,完整约束见下节。
- 已有成绩的项目不能改项目类型：毫秒、毫米、次数和缩放分数不能互换。

## 项目配置与预设

- `domain/event_config.go` 定义起跑方式 `startMode`：`lanes` 分道、`group` 不分道、`break` 分道后抢道。计时与分道独立：计时、报名成绩排序和晋级仍由 `EventKind` 决定，位置容量与中间道分配由 `Event.UsesLanes()` 决定。分道后抢道保存起跑道次，不记录途中抢道轨迹。
- 远度方式 `distanceMode` 为 `jump` 跳跃或 `throw` 投掷；共用毫米成绩、逐次记录和同成绩判定，显示「试跳」或「试投」。`X` 表示犯规，`-` 表示免跳 / 免投；「免投」可作为录入值。
- 接力 `relayLegCount` 是建议棒数，0 表示未指定；任意非负整数均可保存。名单人数与非零建议不符时 `TeamView.sizeWarning` 返回提示，允许创建、报名与编排，混合项目不强制男女比例。
- 配置不适用于当前类型时拒绝保存：田赛不能设置起跑方式，非远度不能设置跳跃 / 投掷，非接力不能设置非零建议棒数。配置缺省时计时项目按分道、远度按跳跃处理，不从项目名推断。
- `service/event_presets.go` 提供 35 个常用项目的初始输入，覆盖短跑、中长跑、跨栏与障碍、接力、跳跃、投掷；界面与 MCP 读取同一目录。预设不与已保存项目关联，所有项目保持自定义名称与配置，选择预设后可调整。
- 已有位置时不能在有道次与无道次之间切换，须先移出；有成绩时不能修改起跑方式。减少道数不能使已有道次越界，减少尝试次数不能截断已有逐次记录，避免隐藏位置或成绩。
- `EventDetail.rules` 由 Go 返回计时、分道、位置名称、尝试名称与默认每组人数；前端展示和本地草稿使用它，打印使用同一领域规则。

## 队伍与接力

- 队伍属于一个队伍项目,队名必填、同一项目同一参赛单位内按规范化文本唯一;参赛单位可不指定。成员必须是同一赛事的运动员,`memberIds` 的数组顺序就是棒次。同一运动员在该项目只能属于一队,同一队不能重复担任棒次;不同项目可以复用运动员。
- 名单可为空或尚未配齐,应用不从自由填写的项目名推断棒数；建议棒数的提示规则见「项目配置与预设」。性别与项目不符在界面提示警告;混合项目不限制男女比例。MCP 文件导入的性别检查见 [mcp.md](mcp.md)。
- `SaveTeam` 创建 / 更新完整队伍,`DeleteTeam` 删除队伍及其报名;这些操作持 service 写锁完成校验和整批事务。队伍保存本身不报名,报名传 `teamId`,排进位置会自动报名。已排进任意轮次的队伍须先移出才能取消报名或删除。
- 队伍处于任一已有成绩的组时,棒次锁定,包括该队本身尚未录成绩的情形;直接调用 service、界面与 MCP 均不能改名单。队名和所属参赛单位可编辑。名单没有逐轮快照,因此不能在决赛换人后让预赛成绩对应另一份名单。
- 运动员在任一队伍中时不能删除,须先从队伍移出;数据库级联不能用于绕过名单保护。运动员列表的报名项数和排位状态包含其队伍的使用情况。
- 个人与队伍参赛方式之间，以及接力与其他类型之间，只允许在没有队伍、报名或已排位置时切换;有成绩时项目类型保护同样适用。
- 数据中的 `athleteId` 与 `teamId` 严格区分;Go `CompetitorID()`、界面查询中的 `competitorId` 仅供名单、草稿和排名统一索引,不把队伍 ID 填进运动员字段。自动编排的计划位置返回 `competitorId`,service 按项目类型落到正确的外键。
- 接力成绩以整队计时、毫秒保存,与径赛共用解析、排名、Q / q 与晋级分组;秩序册和成绩册显示队名及按棒次排列的成员。表格运动员导入只为普通个人项目报名，队伍与全能分别经项目工作区或 MCP 管理。

## 计次、计分与参赛方式

- `count` 只接受非负整数，0 是有效成绩；`score` 采用 `scoreDecimals`（0–3 位）定义的整数缩放，保留固定精度。空白、无有效尝试与有效零值分别处理。
- 计次和计分的 `attemptMode` 为 `single` 一次、`best` 取最好、`sum` 求和；多次模式使用 `attempts[]`，犯规与免试不参与数值汇总，全无有效尝试记 `NM`。单条界面／MCP 写入不允许用最终值绕过多次录入，逐次条数不得超过设置；求和与解析检查整数溢出。
- `rankDirection` 为 `desc` 多／高者优先或 `asc` 少／低者优先，影响报名成绩排序、最好一次、排名与按成绩晋级。计次／计分同最终值并列，不采用田赛次好成绩判定。有成绩后锁定项目类型、小数位、汇总方式与排名方向；已有报名成绩时也不能改项目类型或精度，避免重新解释已保存的数值。
- `participantMode` 为 `athlete` 个人或 `team` 队伍；缺省时接力为队伍，其余为个人。普通队伍项目支持计时、计次、计分，使用同一 `teams / entries.team_id / slots.team_id` 数据。`teamSize` 为普通队伍的非负建议人数，接力使用建议棒数；人数只警告，不阻止先建队。
- `EventDetail.rules` 同时提供队伍参赛、是否逐次录入、成绩名称及单位，界面不从计时与否推断报名主体或录入方式；解析、显示、汇总与排名使用完整项目配置。
- 全能、分项归属、统一报名、计分表与重算确认见 [combined.md](combined.md)，全能不属于 `EventKind`。

## 报名

- **报名决定**进入哪些项目的分组池与选人名单;编排只能使用本项目的报名者。
- **排进位置即自动报名**:把未报名的运动员排进某组时,同一事务里补上报名。
- **取消报名不动已排位置**:已排进组的人要先移出才能取消报名,界面上不给这些人「取消报名」按钮。
- 运动员性别与项目性别不符只警告(混合项目不警告)。
- 学号 / 号码布在赛事内非空时唯一:新建时与已有运动员相同即拒绝(提示改为更新);同名只警告,界面与 MCP 的单条保存通过 `SaveAthleteWithWarnings` 返回警告。防止重复建人。
- **表格批量导入**(粘贴或 CSV):列映射后先预览。有学号按学号、否则按号码布找已有运动员,找到即更新(空单元格不覆盖原值),找不到即新建;没见过的参赛单位自动新建;「报名项目」列按项目全名,或按项目名在同性别(及混合)项目里唯一匹配。任一行有误整批不导入。预览与导入共用同一段计划代码。
- 已排进组的运动员不能删除,须先移出:否则位置空着却留有成绩。

## 报名限制

- 赛事带三项限制 `Meet.EntryLimits`(0 = 不限,0–99):每人限报项数 `athleteEvents`、单位每项限报人数 `unitAthletes`、单位每项限报队数 `unitTeams`。界面在「编辑赛事」里设置(赛事侧栏或赛事列表进入);MCP 经 `create_meet` / `update_meet` 的 `entryLimits` 设置,更新时省略即保持原值。
- **只提示,不拦截**:报名、表格导入、全能统一报名与文件导入都照常保存超出限制的报名。规程之外常有特批,拦截会让录入员无法如实录入;是否取消由人决定。
- **计数**(`domain.CheckEntryLimits`,纯函数):每人项数 = 报名的个人项目各一项 + 全能各一项,全能分项不另计,队伍项目(含接力)不计,作为队员也不计。单位人数按运动员当前所属单位、在一个个人项目或全能内计;单位队数按队伍的参赛单位、在一个队伍项目内计;没有参赛单位的不计入任何单位。同一报名只计一次。
- **读取**:`store.LimitEntries` 一次查询读出全赛事的普通项目报名与全能报名(带单位);未设任何限制时不查。结果不存储,改限制、改报名或运动员换单位后按当前数据重算。
- **提示位置**:报名对话框(个人、队伍、全能)按勾选经 `EntryLimitWarnings` / `CombinedLimitWarnings` 列出「「张三」报 3 项，限报 2 项」「「一班」报 3 人，限报 2 人」,只列所选的人及其单位;报名表以 `EntryView.overEvents` / `overUnit` 标出;运动员列表以 `AthleteRow.overLimit` 标出;表格导入预览写在该行说明里;MCP `add_entries` / `set_combined_entries` 的预览结果带 `warnings`。

## 组与位置

- **组名只存自定义名称**:序号由 `ordinal` 表达;写入时把空白与纯「第N组」存成空串。否则显示会把序号写两遍(「第6组(第6组)」),改序号后名称也会过时。需要可读标签的地方(日志、MCP 查询、打印)用统一的 `HeatLabel`,无名称时为「第N组」。
- **位置由起跑方式决定**:分道与分道后抢道项目的位置是实际起跑道次;八道场地只用二至七道时存 2..7,不压成 1..6。不分道项目和田赛的位置是顺序,编排名单按 1…n 连续显示,不受道数限制。
- **同一轮次里一个运动员只占一个位置**:把他排进某组,同一事务里清空他在本轮次其他组的位置。不同轮次(预赛 → 决赛)可以同时出现。
- **已有成绩的组锁定**:组内任一位置有成绩即为「已比赛」,不能删除,不能被自动编排覆盖;要改位置须先在界面「解锁」。判定只有一处(`HeatFacts.KeepReason`),编排、删除、导入共用。

## 成绩

- **`mark` 是整数**:计时毫秒、田赛毫米、计次次数、计分按小数位缩放;状态 `OK / DNS / DNF / DQ / NM`。浮点会让并列判定出错。
- **解析与格式化只在 `scoring`**:输入 `12.34`、`1:05.67`、`6.52` 按项目类型解析;显示格式统一输出。前端只调用,不自己实现,两份实现会显示出不同的成绩。
- **排名**:有效成绩按项目类型排序(径赛越小越好,田赛越大越好);并列同名次,下一名按并列人数顺延(两人并列第 2,下一名第 4),裁判可以裁定先后(见「并列裁定」)。非 `OK` 状态不排名,排在有效成绩之后。
- 远度与高度的最终成绩由逐次记录推出:远度取最好一次,高度取最后成功高度;同成绩的田赛名次判定规则写在 `scoring` 的表驱动测试里。
- **名次存组内名次**:每次写成绩(或改动有成绩的组)后,service 的 `rescore` 重算该轮次各组名次并存储;轮次总排名读取时现算。
- **晋级**:按「各组前 N 名(`Q`)+ 其余成绩最好的 M 名(`q`)」。`q` 按全轮次的排名取,与总排名同一套规则(田赛同成绩先比次好成绩等),再加裁定。`Q` / `q` 由 `rescore` 在轮次**全部录完**后写入,没录完时清空;卡在最后一个名额上的并列者全部晋级,裁判经「并列裁定」排出先后后多出的人自动去掉。生成下一轮只新建组、只读上一轮成绩,不改任何成绩。
- **录入**:径赛填成绩;远度逐次填(成绩 / `X` 犯规 / `-` 免跳),高度逐高度填 `O` `X` `-`,最终成绩由 Go 推出;没有有效成绩的逐次记录记为 `NM`。整行清空即删除该成绩。
- **高度试跳**:`scoring.ParseTrials` 统一规范大小写、`0 / × / — / －`，每高度最多三个符号，成功后结束本高度，免跳后本高度不再试跳；`ValidateBars` 按高度升序累计连续失败，免跳不清零，成功清零，连续三次失败后不能继续试跳。空白与 `X / XX` 等过程记录可保存；决名次跳跃不在本组逐高度记录模型中。
- **高度录入完成**:`Result.HeightPending` 存在成绩详情中。高度 `ResultInput.heightFinished` 默认为 `false`，保存产生过程记录；界面「结束录入」同批提交本组全部位置并设为 `true`。轮次中有空成绩或过程记录时 `Complete=false`，清除全部 `Q / q`，不能据此生成下一轮；再次修改并保存高度成绩会使该位置恢复过程状态。没有 `heightPending` 的已有数据按已确认成绩读取。全能分项的过程记录使其总成绩保持待完成，积分可随当前最好成绩预览。
- **高度只读预览**:`service.PreviewHeight` 与保存共用 `buildResultEvent`，返回每格规范符号、下一次成功 / 失败 / 免跳的可用性、校验错误、当前最好成绩与组内暂定名次，以及试跳顺序：每格 `state`(`open` 待跳、`done` 已成功 / 免跳 / 三次或第三次连续失败、`skipped` 空着但更高高度已有记录、`out` 此前已淘汰、`off` 有状态或该行校验失败)、下一跳 `next`(最低的仍有人待跳的高度上，先按位置顺序轮完第 1 次，再轮第 2、3 次)与建议的下一高度 `nextHeight`；不写库、不记录开赛时间、不产生变更通知。

## 并列裁定

- **裁定是成绩的一部分**:`Result.TieBreak`(存在 `detail_json`,交换格式 `result.tieBreak`)记录裁判给出的先后,小者在前,相同仍并列,0 为未裁定。它只在按全部排名规则(田赛的次好成绩、高度的失败次数)仍相同的人之间起作用,不会让成绩不同的人换位。
- **整组生效**:并列按轮次划分(`scoring.Ties`,全轮次排名里规则相同的一组,两人以上)。只有这组人**都**带裁定时才按裁定排;有人没带(例如改成绩后新并进来的人)就整组照旧并列,需要重新裁定。裁定不会替没有覆盖到的人决定名次。
- **同一份裁定用于所有排名**:组内名次与 `Q`、全轮次排名与 `q`、轮次总排名、团体总分都经 `scoring.Rank` 读到它。组内的并列是全轮次并列的一部分,所以一次裁定全轮次那一组就同时定下组内先后。
- **写入**:`RuleTies`(界面「裁定并列」)一次提交一个轮次里若干组并列,每组必须给出全部成员的名次,名次在共享名次到「共享名次 + 人数 − 1」之间;全组同一名次即清除裁定。提交后同一批写入重算该轮次名次与 `Q` / `q`,记操作日志 `results.tie`(详情为各人裁定前后的名次)并发出 `results` 变更。名单里有人已不在并列中时返回数据已变化,要求重新读取。MCP 不提供裁定(用户要求)。
- **随成绩失效**:保存成绩时,状态、成绩、逐次记录与逐高度记录都没变(只改备注等)就保留该位置的裁定;任一变化即清除,因为裁定是针对原来的成绩做出的。
- **读取**:`RoundView.ties` 列出本轮次的并列(共享名次、按当前先后排列的成员、是否已裁定)与 `extra`:按当前先后严格排开后晋级人数会减少多少,即这处并列让本轮多出几人晋级;轮次未录完或没有晋级规则时为 0。

## 时间

规则在 `domain/time.go` 与 `domain/schedule.go`,只此一处:service 校验、视图与打印的显示文本、交换格式校验都调用它们;前端不拆分、不拼接显示用的时间文本。

- **三种时间**:
  - 日期 `YYYY-MM-DD`:赛事起止、项目日期、出生日期。
  - 计划时间 `YYYY-MM-DDTHH:mm`:轮次开始时间、组的计划时间与组的实际开赛时间(用户要求),本地墙上时间、精确到分钟、不带时区。
  - 记录时间:毫秒时间戳,如成绩的 `updated_at`、操作日志的时刻、创建时间;显示时换算为本机时区。
- **校验**:日期与计划时间须是真实存在的日历日 / 分钟(`2026-02-30`、`24:00` 拒绝),年份 1–9999,格式严格匹配,不接受空格、秒或时区。只做格式检查会让无效值写进库,之后的排序与运算都会出错。组的预计用时 `durationMinutes` 为 1–1440 分钟的整数,可不填(`ValidDuration`)。
- **运算**:计划时间按 UTC 解析与加减,只当作日历字段,不经本机时区:换算会在夏令时切换处跳过或重复一小时,批量排时与结束时间就会出错。超出 9999 年拒绝。
- **生效计划时间**(`EffectiveScheduled`):组自己的 `scheduledAt` 是「单独指定」;没填时沿用所在轮次的 `scheduledAt`(`inherited` 为真)。显示、排序、打印都用生效时间;组的 `scheduledAt` 只存单独指定的值,轮次开始时间改了,沿用它的组跟着变,不需要逐组改写。
- **结束时间**(`HeatEnd` / `ScheduledEnd`):生效计划时间 + 预计用时;任一缺失就没有结束时间。`HeatView.endAt` 返回它。
- **时间冲突**:同一运动员(队伍展开为队员,含全能分项)的两个组时间重叠,或间隔不足设置里的最短休息时间,列为冲突;没有预计用时的组按时间点计,没有计划时间的组不参与。只提示,不拦截任何保存(用户要求)。完整规则见 [arrange.md](arrange.md)「冲突检查」。
- **项目的日子**:`EventDay` = 项目日期,未填时为赛事开始日期。项目日期只是没有计划时间时的默认日子,界面不提供输入(项目落在哪天由轮次与组的时间决定,两个入口会让用户不知道以哪个为准);它经 MCP `save_event` 与交换格式写入,界面编辑项目时原样保留。界面与打印显示的日子用 `PlannedDay`,即该项目最早计划时间(轮次开始时间与组的单独时间里最早的一个)所在的日子,没有任何时间才用 `EventDay`(`EventDetail.day`)。编排、成绩、打印都以它为参照。
- **赛事日期外的提示**:轮次或组的计划时间所在日子不在赛事起止日期内(`OutsideMeet`;未填结束日期即只有开始那天)时,保存前提示「时间不在赛事日期内」,批量排时预览提示「N 组不在赛事日期内」;只提示,不拦截保存。判断只在 service(`ScheduleWarning`、`SetRoundStart`、批量排时预览的 `warnings`),界面与 MCP 共用。
- **显示**:
  - 计划时间与参照日同一天只显示 `HH:mm`,否则显示 `YYYY-MM-DD HH:mm`;没有参照日(批量排时预览)始终带日期。`HeatView` 内嵌的 `HeatTimes` 给出生效时间 `effectiveAt`、是否沿用轮次 `scheduleInherited`、文本 `scheduledText`、`durationText`(`5 分钟`)与 `endAt`;`RoundView.scheduledText` 显示轮次开始时间。编排草稿里改过的组经绑定 `Arrange.heatPlan` 校验并取得同样的文本。
  - 批量排时预览的原安排 / 新安排带日期,沿用的时间标「（沿用轮次）」,有预计用时时接「 · N 分钟」(`planText`)。
  - 日程视图(`Timetable`)里轮次与组的时间以所在那天为参照,只显示时刻;跨到第二天的结束时间带日期。冲突里另一组的时间始终带日期。
  - 日期范围同一天只显示一个日期,否则 `开始 – 结束`(`MeetView.datesText`、打印页眉)。
  - 打印的日子带星期(`DayText`:`2026-11-12 周四`):竞赛日程表的日期标题与秩序册、成绩册的项目标题。
  - 记录时间显示到分钟 `YYYY-MM-DD HH:mm`,不随「今天」变化,页面不重读时文字也不会过时。
- **每组成绩的最后修改时间**:读取组时一并取该组现有成绩 `updated_at` 的最大值(`Heat.ResultsUpdatedAt`,不存储、不进指纹与 JSON),`HeatView.resultsUpdatedText` 显示。写成绩、排位变化以及重算改动名次或晋级的成绩都会更新;清空的成绩不再计入。
- **实际开赛时间**(`Heat.StartedAt`,计划时间格式,空 = 未记录):
  - 自动记录:`SaveResults` 写入后该组有成绩、且还没有开赛时间时,同一批写入把它设为当时时刻(service 时钟 `store.Now` 按 service 时区换成墙上时间,`domain.WallClock`);已有值不覆盖。界面与 MCP `set_results` 都经这里。
  - 手动修改与清除:`SetHeatStarted`(界面与 MCP `set_heat_started` 共用)直接写入,记操作日志 `heat.started`(详情含前后值)并发出 `heats` 变更;值不变时不写。
  - 它不是编排:不进组指纹,不影响锁定,修改它不会让编排草稿或位置作废。清空全部成绩不清它,要清除就手动清除;编排保存只改位置相关的列,也不动它。批量排时间的预览指纹包含组的全部状态,预览之后改了开赛时间须重新预览。
  - 显示:`HeatStart` 内嵌在 `HeatView` 与 `TimetableHeat`:`startedAt`、`startedText`(与计划时间同样以参照日显示)、`startDeltaText`(与生效计划时间的差,`StartDeltaText`:`准时`、`晚 12 分钟`、`早 5 分钟`、`晚 1 小时 5 分钟`、`晚 1 天 2 小时`,跨午夜与跨天照算,为零的单位不写;任一时间缺失为空)。成绩页组标题与日程页时间列显示它;成绩册在组标题后印「实际开赛 HH:mm」,没有就不印,计划时间不印(成绩册只记实际发生的事);秩序册不印。
- **检录时间**(`CheckInAt`):生效计划时间减去「设置 → 编排」的检录提前时间(0–240 分钟,默认 20,`ValidCheckInLead`);提前时间为 0 或组没有计划时间时没有检录时间。不存储,只在检录单上印,日程页与秩序册不显示。
- **成绩时间**:「设置 → 打印」打开「成绩时间」(默认关)后,成绩册在每组成绩后印该组成绩的最后修改时间(`ResultsUpdatedAt`,到分钟);只排名的轮次印在排名表后。
- **打印时间**:秩序册、成绩册与检录单末尾印「打印时间」,取生成 HTML 的时刻,按记录时间显示。
- **竞赛日程表**:秩序册在项目之前印「竞赛日程表」(「设置 → 打印」可关,默认开),与日程页同一份 `Timetable`:按天、按时间列出序号(整张表连续编号)、时间、类别(径赛 / 田赛,计次与计分写项目类型)、项目、轮次、组数与人数(口径同日程页,见 [arrange.md](arrange.md)「竞赛日程」),只印已安排时间的轮次,没有时间的轮次不印;只含本次打印选中的项目(选全能即含其分项),一个都没有就整节不印。成绩册不印。表格行不跨页拆开,每天的日期标题不与表格分开(`break-inside` / `break-after: avoid`,并写旧的 `page-break-*`)。
- **轮次开始时间的写入**:`SetRoundStart`(界面与 MCP `set_round_start` 共用)直接写入、记操作日志 `round.scheduled` 并发出 `heats` 变更;值不变时不写。它不改任何组,所以不影响组指纹与编排草稿,已比赛的组若沿用它,显示的时间也随之变化,位置与成绩不变。
- **项目列表顺序**(`ScheduleOrder`,项目列表、MCP `list_events`、打印选择与秩序册 / 成绩册共用):普通项目先按 `PlannedDay`,再按该项目最早的计划时间(`EarliestScheduled`:轮次开始时间与组的单独时间),最后按创建顺序;没有日子或时间的排在有的之后。全能分项不参与时间排序,按原顺序排在普通项目之后,分项顺序属于全能。交换格式导出与其他内部读取保持创建顺序,时间变化不会改动导出文件。`EventRow.timeText` 显示最早的计划时间,整张列表写法一致:所有项目都在赛事首日时只显示时刻(没有时间的留空);只要有项目在别的日子,每一行都带日期,没有时间的只显示日子。只按各行自己是否在首日决定,同一列就会有的带日期、有的不带。

## 删除与级联

- 删组:删它的位置与成绩。删项目:删它的轮次、组、位置、成绩与报名。删赛事:删以上全部、运动员与参赛单位。级联由外键完成(→ [storage.md](storage.md))。
- 删除前确认对话框给出将删除的组数与成绩数(见 [copywriting.md](copywriting.md) 示例)。
- 有成绩的组(及含这类组的赛事 / 项目)只能在界面上删,MCP 一律拒绝(→ [mcp.md](mcp.md))。

## 操作日志

- service 的每个写操作写一条日志:时刻、来源(`ui` / `mcp` / `system`)、动作、涉及的项目 / 组、简短说明与 JSON 详情。
- 日志写入失败只记应用日志,不影响业务。
- 新增写操作必须同时登记它的日志动作名。现有:`meet.created / updated / deleted / imported`、`unit.created / updated / deleted`、`athlete.created / updated / deleted / imported`、`event.created / updated / deleted`、`team.created / updated / deleted`、`entry.added / removed / seed`、`board.saved / reset`、`heats.scheduled`、`round.scheduled`、`heat.started`、`results.saved / tie`、`settings.preferences / mcp`、`combined.created / updated / deleted / entries / rules`。
- 成绩日志同时保留输入位置的原成绩与新成绩完整记录,包括逐次记录与备注;只修改备注同样可追查。设置日志不含令牌。
- 日志只读:`ListAudit` 按时刻倒序(同一时刻按写入顺序)分页读取,可按赛事与来源筛选;每页最多 200 条,以上一页最后一行的时刻与 id 继续,固定两次查询(日志与赛事名称),不随条数增长。动作与来源的中文显示文本由 `service/audit.go` 映射,新增动作同时登记显示文本,单测检查没有遗漏。赛事删除后其日志保留,赛事名称为空。

## 团体总分

- 按已完成的决赛总排名或全能总排名换算得分并汇总到参赛单位；分项不单独计分、队伍计一次、单位同分并列（用户要求），完整规则见 [team-scoring.md](team-scoring.md)。

## 赛事组别

- 赛事统一组别、单位多组归属、运动员默认组别、报名提示与调整确认完整规则见 [groups.md](groups.md)。项目身份按性别、项目名与组别确定；全能分项继承父项组别。
