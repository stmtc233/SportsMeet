# 领域模型:赛事、项目、报名、成绩

术语见 [AGENTS.md](../../AGENTS.md) §2。实现在 `internal/domain/`(实体与校验)、`internal/service/`(写入口)、`internal/scoring/`(成绩)。

## 层级

```
赛事 meet
├── 参赛单位 unit
├── 运动员 athlete            ← 属于赛事,各项目共用
└── 项目 event                ← 一个单项
    ├── 接力队 team           ← 仅接力，成员来自赛事运动员，按棒次排列
    ├── 报名 entry            ← 运动员(接力为队伍)进入本项目
    └── 轮次 round
        └── 组 heat
            └── 位置 slot → 成绩 result
```

- **项目 = 一个单项**:必带性别(男 / 女 / 混合)与项目名 `discipline`,组别 `groupLabel` 可选。男女、不同距离必须拆成不同项目。原因:不加约束时,经 MCP 导入的报名表会把男女、50m 与 100m 混进同一项目,之后分组、排名全错。不要为省事放松这条校验,也不要让项目可以不属于赛事。
- **项目名称留空时自动组成**:「性别前缀 + `discipline` + 空格 + `groupLabel`」,如「男子100m 初中组」。组成规则只在 Go 一处实现,前端预览也调用它。
- **同一赛事内 `gender + discipline + groupLabel` 不重复**;`discipline` 宽松比较(`100 米` = `100m`,`4x100M` = `4×100m`)。
- 项目、运动员创建时指定所属赛事,之后不可改。
- **轮次**:新建项目自带一个决赛;赛制选「预赛 + 决赛」时在决赛前加预赛并带晋级规则。每个阶段在一个项目里至多一个轮次,序号按阶段先后(预赛 → 次赛 → 半决赛 → 决赛)。预赛已有组时不能改回「直接决赛」。
- 接力队伍与棒次由 `service/teams.go` 管理;报名、编排、成绩、排名晋级与导入导出均按队处理,完整约束见下节。
- 已有成绩的项目不能改项目类型:毫秒与毫米不能互换。

## 项目配置与预设

- `domain/event_config.go` 定义起跑方式 `startMode`：`lanes` 分道、`group` 不分道、`break` 分道后抢道。计时与分道独立：计时、报名成绩排序和晋级仍由 `EventKind` 决定，位置容量与中间道分配由 `Event.UsesLanes()` 决定。分道后抢道保存起跑道次，不记录途中抢道轨迹。
- 远度方式 `distanceMode` 为 `jump` 跳跃或 `throw` 投掷；共用毫米成绩、逐次记录和同成绩判定，显示「试跳」或「试投」。`X` 表示犯规，`-` 表示免跳 / 免投；「免投」可作为录入值。
- 接力 `relayLegCount` 是建议棒数，0 表示未指定；任意非负整数均可保存。名单人数与非零建议不符时 `TeamView.sizeWarning` 返回提示，允许创建、报名与编排，混合项目不强制男女比例。
- 配置不适用于当前类型时拒绝保存：田赛不能设置起跑方式，非远度不能设置跳跃 / 投掷，非接力不能设置非零建议棒数。配置缺省时计时项目按分道、远度按跳跃处理，不从项目名推断。
- `service/event_presets.go` 提供 30 个常用项目的初始输入，覆盖短跑、中长跑、跨栏与障碍、接力、跳跃、投掷；界面与 MCP 读取同一目录。预设不与已保存项目关联，所有项目保持自定义名称与配置，选择预设后可调整。
- 已有位置时不能在有道次与无道次之间切换，须先移出；有成绩时不能修改起跑方式。减少道数不能使已有道次越界，减少尝试次数不能截断已有逐次记录，避免隐藏位置或成绩。
- `EventDetail.rules` 由 Go 返回计时、分道、位置名称、尝试名称与默认每组人数；前端展示和本地草稿使用它，打印使用同一领域规则。

## 接力

- 队伍属于一个接力项目,队名必填、同一项目同一参赛单位内按规范化文本唯一;参赛单位可不指定。成员必须是同一赛事的运动员,`memberIds` 的数组顺序就是棒次。同一运动员在该项目只能属于一队,同一队不能重复担任棒次;不同项目可以复用运动员。
- 名单可为空或尚未配齐,应用不从自由填写的项目名推断棒数；建议棒数的提示规则见「项目配置与预设」。性别与项目不符在界面提示警告;混合项目不限制男女比例。MCP 文件导入的性别检查见 [mcp.md](mcp.md)。
- `SaveTeam` 创建 / 更新完整队伍,`DeleteTeam` 删除队伍及其报名;这些操作持 service 写锁完成校验和整批事务。队伍保存本身不报名,报名传 `teamId`,排进位置会自动报名。已排进任意轮次的队伍须先移出才能取消报名或删除。
- 队伍处于任一已有成绩的组时,棒次锁定,包括该队本身尚未录成绩的情形;直接调用 service、界面与 MCP 均不能改名单。队名和所属参赛单位可编辑。名单没有逐轮快照,因此不能在决赛换人后让预赛成绩对应另一份名单。
- 运动员在任一接力队中时不能删除,须先从队伍移出;数据库级联不能用于绕过名单保护。运动员列表的报名项数和排位状态包含其接力队的使用情况。
- 接力与个人项目之间只允许在没有队伍、报名或已排位置时切换;有成绩时项目类型保护同样适用。
- 数据中的 `athleteId` 与 `teamId` 严格区分;Go `CompetitorID()`、界面查询中的 `competitorId` 仅供名单、草稿和排名统一索引,不把队伍 ID 填进运动员字段。自动编排的计划位置返回 `competitorId`,service 按项目类型落到正确的外键。
- 接力成绩以整队计时、毫秒保存,与径赛共用解析、排名、Q / q 与晋级分组;秩序册和成绩册显示队名及按棒次排列的成员。表格运动员导入只为个人项目报名,接力队伍经项目工作区或 MCP 管理。

## 报名

- **报名决定**进入哪些项目的分组池与选人名单;编排只能使用本项目的报名者。
- **排进位置即自动报名**:把未报名的运动员排进某组时,同一事务里补上报名。
- **取消报名不动已排位置**:已排进组的人要先移出才能取消报名,界面上不给这些人「取消报名」按钮。
- 运动员性别与项目性别不符只警告(混合项目不警告)。
- 学号 / 号码布在赛事内非空时唯一:新建时与已有运动员相同即拒绝(提示改为更新);同名只警告,界面与 MCP 的单条保存通过 `SaveAthleteWithWarnings` 返回警告。防止重复建人。
- **表格批量导入**(粘贴或 CSV):列映射后先预览。有学号按学号、否则按号码布找已有运动员,找到即更新(空单元格不覆盖原值),找不到即新建;没见过的参赛单位自动新建;「报名项目」列按项目全名,或按项目名在同性别(及混合)项目里唯一匹配。任一行有误整批不导入。预览与导入共用同一段计划代码。
- 已排进组的运动员不能删除,须先移出:否则位置空着却留有成绩。

## 组与位置

- **组名只存自定义名称**:序号由 `ordinal` 表达;写入时把空白与纯「第N组」存成空串。否则显示会把序号写两遍(「第6组(第6组)」),改序号后名称也会过时。需要可读标签的地方(日志、MCP 查询、打印)用统一的 `HeatLabel`,无名称时为「第N组」。
- **位置由起跑方式决定**:分道与分道后抢道项目的位置是实际起跑道次;八道场地只用二至七道时存 2..7,不压成 1..6。不分道项目和田赛的位置是顺序,编排名单按 1…n 连续显示,不受道数限制。
- **同一轮次里一个运动员只占一个位置**:把他排进某组,同一事务里清空他在本轮次其他组的位置。不同轮次(预赛 → 决赛)可以同时出现。
- **已有成绩的组锁定**:组内任一位置有成绩即为「已比赛」,不能删除,不能被自动编排覆盖;要改位置须先在界面「解锁」。判定只有一处(`HeatFacts.KeepReason`),编排、删除、导入共用。

## 成绩

- **`mark` 是整数**:径赛毫秒,田赛毫米;状态 `OK / DNS / DNF / DQ / NM`。浮点会让并列判定出错。
- **解析与格式化只在 `scoring`**:输入 `12.34`、`1:05.67`、`6.52` 按项目类型解析;显示格式统一输出。前端只调用,不自己实现,两份实现会显示出不同的成绩。
- **排名**:有效成绩按项目类型排序(径赛越小越好,田赛越大越好);并列同名次,下一名按并列人数顺延(两人并列第 2,下一名第 4)。非 `OK` 状态不排名,排在有效成绩之后。
- 远度与高度的最终成绩由逐次记录推出:远度取最好一次,高度取最后成功高度;同成绩的田赛名次判定规则写在 `scoring` 的表驱动测试里。
- **名次存组内名次**:每次写成绩(或改动有成绩的组)后,service 的 `rescore` 重算该轮次各组名次并存储;轮次总排名读取时现算。
- **晋级**:按「各组前 N 名(`Q`)+ 其余成绩最好的 M 名(`q`)」。`Q` / `q` 由 `rescore` 在轮次**全部录完**后写入,没录完时清空;卡在最后一个名额上的并列者全部晋级,由裁判手动去掉多余的人。生成下一轮只新建组、只读上一轮成绩,不改任何成绩。
- **录入**:径赛填成绩;远度逐次填(成绩 / `X` 犯规 / `-` 免跳),高度逐高度填 `O` `X` `-`,最终成绩由 Go 推出;没有有效成绩的逐次记录记为 `NM`。整行清空即删除该成绩。

## 删除与级联

- 删组:删它的位置与成绩。删项目:删它的轮次、组、位置、成绩与报名。删赛事:删以上全部、运动员与参赛单位。级联由外键完成(→ [storage.md](storage.md))。
- 删除前确认对话框给出将删除的组数与成绩数(见 [copywriting.md](copywriting.md) 示例)。
- 有成绩的组(及含这类组的赛事 / 项目)只能在界面上删,MCP 一律拒绝(→ [mcp.md](mcp.md))。

## 操作日志

- service 的每个写操作写一条日志:时刻、来源(`ui` / `mcp` / `system`)、动作、涉及的项目 / 组、简短说明与 JSON 详情。
- 日志写入失败只记应用日志,不影响业务。
- 新增写操作必须同时登记它的日志动作名。现有:`meet.created / updated / deleted / imported`、`unit.created / updated / deleted`、`athlete.created / updated / deleted / imported`、`event.created / updated / deleted`、`team.created / updated / deleted`、`entry.added / removed / seed`、`board.saved / reset`、`heats.scheduled`、`results.saved`、`settings.preferences / mcp`。
- 成绩日志同时保留输入位置的原成绩与新成绩完整记录,包括逐次记录与备注;只修改备注同样可追查。设置日志不含令牌。
