# 领域模型:赛事、项目、报名、成绩

术语见 [AGENTS.md](../../AGENTS.md) §2。实现在 `internal/domain/`(实体与校验)、`internal/service/`(写入口)、`internal/scoring/`(成绩)。

## 层级

```
赛事 meet
├── 参赛单位 unit
├── 运动员 athlete            ← 属于赛事,各项目共用
└── 项目 event                ← 一个单项
    ├── 报名 entry            ← 运动员(接力为队伍)进入本项目
    └── 轮次 round
        └── 组 heat
            └── 位置 slot → 成绩 result
```

- **项目 = 一个单项**:必带性别(男 / 女 / 混合)与项目名 `discipline`,组别 `groupLabel` 可选。男女、不同距离必须拆成不同项目。原因:不加约束时,经 MCP 导入的报名表会把男女、50m 与 100m 混进同一项目,之后分组、排名全错。不要为省事放松这条校验,也不要让项目可以不属于赛事。
- **项目名称留空时自动组成**:「性别前缀 + `discipline` + 空格 + `groupLabel`」,如「男子100m 初中组」。组成规则只在 Go 一处实现,前端预览也调用它。
- **同一赛事内 `gender + discipline + groupLabel` 不重复**;`discipline` 宽松比较(`100 米` = `100m`,`4x100M` = `4×100m`)。
- 项目、运动员创建时指定所属赛事,之后不可改。
- **轮次**:新建项目自带一个决赛;赛制选「预赛 + 决赛」时在决赛前加预赛并带晋级规则。每个阶段在一个项目里至多一个轮次,序号按阶段先后(预赛 → 次赛 → 半决赛 → 决赛)。预赛已有组时不能改回「直接决赛」。
- **接力暂不支持**:service 拒绝新建接力项目,表格导入与交换格式导入跳过接力(后者给警告)。数据表与交换格式已为接力留好结构。
- 已有成绩的项目不能改项目类型:毫秒与毫米不能互换。

## 报名

- **报名决定**进入哪些项目的分组池与选人名单;编排只能使用本项目的报名者。
- **排进位置即自动报名**:把未报名的运动员排进某组时,同一事务里补上报名。
- **取消报名不动已排位置**:已排进组的人要先移出才能取消报名,界面上不给这些人「取消报名」按钮。
- 运动员性别与项目性别不符只警告(混合项目不警告)。
- 学号 / 号码布在赛事内非空时唯一:新建时与已有运动员相同即拒绝(提示改为更新);同名只警告。防止重复建人。
- **表格批量导入**(粘贴或 CSV):列映射后先预览。有学号按学号、否则按号码布找已有运动员,找到即更新(空单元格不覆盖原值),找不到即新建;没见过的参赛单位自动新建;「报名项目」列按项目全名,或按项目名在同性别(及混合)项目里唯一匹配。任一行有误整批不导入。预览与导入共用同一段计划代码。
- 已排进组的运动员不能删除,须先移出:否则位置空着却留有成绩。

## 组与位置

- **组名只存自定义名称**:序号由 `ordinal` 表达;写入时把空白与纯「第N组」存成空串。否则显示会把序号写两遍(「第6组(第6组)」),改序号后名称也会过时。需要可读标签的地方(日志、MCP 查询、打印)用统一的 `HeatLabel`,无名称时为「第N组」。
- **位置是实际物理道次**:八道场地只用二至七道时存 2..7,不压成 1..6。
- **同一轮次里一个运动员只占一个位置**:把他排进某组,同一事务里清空他在本轮次其他组的位置。不同轮次(预赛 → 决赛)可以同时出现。
- **已有成绩的组锁定**:组内任一位置有成绩即为「已比赛」,不能删除,不能被自动编排覆盖;要改位置须先在界面「解锁」。判定只有一处(`HeatFacts.KeepReason`),编排、删除、导入共用。

## 成绩

- **`mark` 是整数**:径赛毫秒,田赛毫米;状态 `OK / DNS / DNF / DQ / NM`。浮点会让并列判定出错。
- **解析与格式化只在 `scoring`**:输入 `12.34`、`1:05.67`、`6.52` 按项目类型解析;显示格式统一输出。前端只调用,不自己实现,两份实现会显示出不同的成绩。
- **排名**:有效成绩按项目类型排序(径赛越小越好,田赛越大越好);并列同名次,下一名按并列人数顺延(两人并列第 2,下一名第 4)。非 `OK` 状态不排名,排在有效成绩之后。
- 远度与高度的最终成绩由逐次记录推出:远度取最好一次,高度取最后成功高度;同成绩的田赛名次判定规则写在 `scoring` 的表驱动测试里。
- **名次存组内名次**:每次写成绩(或改动有成绩的组)后,service 的 `rescore` 重算该轮次各组名次并存储;轮次总排名读取时现算。
- **晋级**:按「各组前 N 名(`Q`)+ 其余成绩最好的 M 名(`q`)」。`Q` / `q` 由 `rescore` 在轮次**全部录完**后写入,没录完时清空;卡在最后一个名额上的并列者全部晋级,由裁判手动去掉多余的人。生成下一轮只新建组、只读上一轮成绩,不改任何成绩。
- **录入**:径赛填成绩;远度逐次填(成绩 / `X` 犯规 / `-` 免跳),高度逐高度填 `O` `X` `-`,最终成绩由 Go 推出;没有有效成绩的逐次记录记为 `NM`。整行清空即删除该成绩。

## 删除与级联

- 删组:删它的位置与成绩。删项目:删它的轮次、组、位置、成绩与报名。删赛事:删以上全部、运动员与参赛单位。级联由外键完成(→ [storage.md](storage.md))。
- 删除前确认对话框给出将删除的组数与成绩数(见 [copywriting.md](copywriting.md) 示例)。
- 有成绩的组(及含这类组的项目)只能在界面上删,MCP 一律拒绝(→ [mcp.md](mcp.md))。

## 操作日志

- service 的每个写操作写一条日志:时刻、来源(`ui` / `mcp` / `system`)、动作、涉及的项目 / 组、简短说明与 JSON 详情。
- 日志写入失败只记应用日志,不影响业务。
- 新增写操作必须同时登记它的日志动作名。现有:`meet.created / updated / deleted / imported`、`unit.created / updated / deleted`、`athlete.created / updated / deleted / imported`、`event.created / updated / deleted`、`entry.added / removed / seed`、`board.saved / reset`、`results.saved`。
