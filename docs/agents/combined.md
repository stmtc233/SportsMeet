# 全能与分项

实体在 `domain/combined.go`，计分在 `scoring/combined.go`，数据在 `store/combined.go`，写入口与规则预览在 `service/combined*.go`，界面在 `features/combined/`。

## 归属与结构

- 全能 `combined` 属于赛事，拥有至少两个个人分项；分项仍是 `event`，通过 `combined_id` 归属全能，并通过 `combined_components` 保存顺序及计分表。普通100m与同组别全能100m可同时存在，项目身份为「全能归属（普通项目为空）+ 性别 + 项目名 + 组别」。全能本身按「性别 + 全能名 + 组别」唯一。
- 分项继承全能的性别和组别，项目名不得重复；只采用一个决赛轮次，可分多组，汇总只读取该决赛每人的唯一成绩。全能不把分项当作轮次，也不混入接力或普通队伍项目。
- `SaveCombined` 在持 service 写锁期间校验全部分项与计分表，再在单个事务保存全能、分项和决赛；任何校验或数据库失败均不留下部分结构。有位置时不能修改分项结构和成绩配置；空分项可重新配置并保留统一报名。
- 分项由全能管理，`SaveEvent`、`DeleteEvent` 拒绝直接编辑或删除分项；分项编排与成绩录入仍使用现有服务。删除全能级联删除其分项与报名，保留其他普通项目；MCP 不能删除已有成绩的全能。

## 统一报名

- `combined_entries` 是全能名单，`SetCombinedEntries` 接受完整运动员 ID 列表，一次更新全能及全部分项报名。运动员必须属于本赛事且不重复；性别不符在读模型提示警告。
- 取消报名要求该运动员在所有分项均无排位；任何分项还有位置则整批拒绝。直接增删分项报名被拒绝，编排也不能把未在全能报名的人排进分项，防止分项名单分叉。
- 名单保存失败保留界面选择；业务写入与日志、通知共用 service 写入口。

## 计分表

- 每个分项保存独立的 `PointRule`：`bands[]` 为整数成绩阈值与非负整数积分，`invalidPolicies` 指定 `DNS / DNF / DQ / NM` 各自的 `zero`（该项零分）或 `exclude`（不列总排名）。创建界面可调整每种状态。
- 档位从高标准到低标准排列：计时及低值优先项目阈值严格递增，其余严格递减；积分不能随标准降低而增加。达到某档即取该档积分，边界包含阈值，不插值，未达到最低标准得零分。
- 表格输入是「成绩、积分」两列，支持制表符、逗号或空格分隔及可选的「成绩／积分」表头；先按该分项的成绩单位解析，再校验顺序和状态策略。预览、保存与 MCP 共用 Go 解析。阈值显示保留完整毫秒、毫米或分数精度，避免再编辑时改变档位。
- 规则属于赛事中的全能，不引用会被外部修改的模板。`rule_version` 是规则版本；计分表修改通过 `PreviewCombinedRules` → `ApplyCombinedRules`，包括无成绩时的计分表修改。预览返回原、新逐项积分、总分、名次和资格状态；确认必须携带指纹与 `confirmed=true`。
- 指纹覆盖请求、赛事全能结构、项目配置、完整轮次成绩和运动员资料；提交在同一写锁内重新计算，变化返回 `E_STALE`，不更新规则。成功整批更新分项计分表和规则版本，保留原始成绩，写 `combined.rules` 日志。

## 总成绩与打印

- 原始分项成绩与已保存规则是事实源，积分、总分、总排名读取时由 Go 计算，不保存可独立编辑的累计总分。分项成绩变化通过赛事事件使全能界面重新读取。
- 未录入成绩标为待录，不记零分；有效零成绩照常计分；无效成绩按其规则计零分或取消该人的总排名资格。未录完显示暂列排名，全部报名者的分项都有处理结果后显示正式排名；无报名时不视为完成。
- 合格者按总分降序排列，同分并列同名次，下一名顺延；失去资格者保留逐项结果与累计积分，不列名次。积分求和检查整数溢出。
- 全能与普通项目同列在「项目」页（类型筛选「全能」），点一行进入全能工作区，提供分项、报名、总成绩与计分规则；分项工作区返回所属全能。秩序册与成绩册选择全能时包含全部分项和统一名单／总成绩，不需要逐个勾选分项。总成绩每张表最多四个分项，分表保留号码、姓名、总分与名次，适应 A4 纸宽；每格上为分项成绩、下为积分（失去资格写「不列名次」）。
- 打印时全能标题按 `combinedTitle` 补上性别与组别（名称里已有的不重复，如「男子校园三项全能 初一组」），同名的男女全能不会分不清；秩序册在名单前列出各分项的顺序与最早计划时间，竞赛日程表里分项写成「全能标题 · 分项名」。

- 全能只按完成后的总排名贡献一次团体得分，分项不重复计分，详见 [team-scoring.md](team-scoring.md)。

## MCP 与交换格式

- `list_combined / get_combined / parse_point_rule` 查询；`preview_save_combined → save_combined` 创建或编辑；`preview_combined_entries → set_combined_entries` 统一报名；`preview_delete_combined → delete_combined` 删除；规则修改使用独立的预览确认工具。
- 批量写与删除继续遵循 [mcp.md](mcp.md)；分项成绩覆盖与清空保护同普通项目。
- 交换格式 v3 在 `events[]` 中保存分项，在 `combineds[]` 中保存全能、分项引用、规则、版本与名单；引用、归属、决赛结构及分项名单一致性在导入前校验。同赛事导入复用全能时，分项与计分表须一致，避免绕过规则重算确认。完整字段见 [交换格式](../interchange-format.md)。
