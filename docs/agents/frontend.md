# 前端约定(`src/`)

界面组件与 token 见 [design-system.md](design-system.md);文案见 [copywriting.md](copywriting.md)。

## 代码结构

- React;按 `src/features/<area>/` 拆分,单文件 ≲ 400 行。页面切换是 `src/app/nav.tsx` 里的路由状态(不用路由库),有未保存改动的页面经 `useLeaveGuard` 登记,离开前统一确认。
- 外壳用 `src/app/ErrorBoundary.tsx` 包住全部页面:某个页面渲染时抛错,窗口显示提示与「返回全部赛事」,而不是整窗空白。它只兜底渲染错误;读写失败照常经数据钩子的 `error` 与 `act()` 提示。
- 版本号只写在 `mygo.config.ts`:Go 启动时经 `mygo.App.Version()` 读入 `service.Version`,「关于」与导出文件都用它;未打包运行(单测)时为 `dev`。
- **只经生成的 `src/mygo.ts` 调用 Go**;页面组件不直接调用,读取经各 feature 的 `use*` 数据钩子(底层 `lib/useData.ts`),写入一律经 `*Controller`,由 `lib/action.ts` 的 `act()` 统一弹出结果提示(`StToast`)。
- **调用 Go 的文件只有 `src/lib/` 与各 feature 的 `controller.ts` / `*Controller.ts` / `data.ts`**,其余文件只从 `src/mygo.ts` 引入类型(`import type` 或 `type X`)。调用散在组件里,同一个写入就会出现几种提示与刷新方式。`scripts/check-design-system.sh` 的 `bindings` 规则把关:基线里列出尚未收进 `controller` 的文件,只减不增;改到其中的文件时把调用收进 `controller`,再运行 `scripts/check-design-system.sh --update-baseline`。
- `act()` 将 mygo 无返回值调用的 `null` 与 `undefined` 都视为成功,供调用方区分成功和异常;否则桌面操作已完成仍会被当作失败。
- Go 返回的错误码在 `lib/errors.ts` 一处映射为中文提示,页面不各写一份;校验错误由 service 直接给出成文的中文。
- 纯逻辑(按钮可用性、草稿合并、排序显示)写成可单测的纯函数,不埋在组件里。
- **时间**:显示用的时间文本(计划时间、日期范围、记录时间)都由 Go 算好随数据返回,规则见 [domain.md](domain.md)「时间」。表单里把计划时间拆成日期与时刻、合并回存储格式、取今天作默认值,只在 `lib/wallTime.ts`(有单测);组件不自己拆时间字符串。

## 导航

- 赛事侧栏(`App.tsx`)按阶段分组:「总览」单列在最上;「赛前」赛事设置、项目、报名、日程;「比赛」团体总分;「输出」打印;底部是「设置」与「全部赛事」。分组标题用 `StNavHeading`,与入口放在同一个 `StNavGroup` 里,选中底板只停在入口上。
- 「赛事设置」(`features/setup/`)是一页纵向的分组卡片。赛事信息与报名限制共用一个保存栏:有修改时出现,离开先确认,保存成功后等重新读取的赛事到达再清掉草稿,否则输入框会先跳回旧值。团体总分的开关与计分规则(`team-scoring/TeamScoringSection.tsx`)、赛事文件的导出与导入到本赛事(`exchange/ExchangeSection.tsx`)各自直接生效。新建赛事与赛事列表的「编辑」用 `MeetDialog`,与这一页共用 `meets/MeetFields.tsx` 的输入框。
- 项目工作区与全能工作区的路由带 `returnTo`,由 `useNav().go` 经 `withReturn` 自动填上:从赛事页进入时是那一页,项目之间、全能之间跳转沿用当前的来源,从全能进分项时是该全能。返回按钮按它写「返回总览」「返回日程」「返回全能」等(`backTo`),侧栏高亮来源页(`sideTab`)。页面不自己拼返回目标:各写一份就会出现从总览进来却返回项目列表的情况。
- 项目列表点一行打开该项目上次所在的 Tab(编排 / 成绩),没有记录或上次在报名时打开报名(`lastEventTab`);总览、日程、团体总分等入口直接指定 Tab。

## 变更事件与刷新

- service 写入成功后经 mygo 事件广播(事件声明在 `internal/bind/`),前端按事件重新读取相关数据。界面自己的写入与 MCP 的写入走同一条路径,持久化数据由 service 的查询结果驱动。编排保存用返回的完整详情重新建立草稿,确认新增组的真实 ID 与已保存状态(见 [arrange.md](arrange.md)「本地草稿,一次保存」)。
- **事件引起的重新读取按数据合并**:第一次立即执行,500ms 窗口内的后续事件合并为窗口结束时的一次。批量导入会连续发出大量事件,不合并会造成连串重读。
- **读取结果按键缓存**:`useData` 第四个参数是缓存键,须写全读取依赖的全部参数(`events:<meetId>`、`event:<eventId>`)。页面再次打开时先显示上一次的结果,同时重新读取,新结果到了再替换;否则每次切页都先空白、闪出「还没有……」再填上内容。只保留最近 40 份。报表 HTML 与操作日志不缓存(前者大,后者自带分页合并)。先显示的旧结果与「别处写入后重新读取」走同一条合并路径:编排草稿、成绩输入照常按指纹 / 逐位置合并,不需要另写判断。

## 视图状态

页面离开再回来时,保持用户当时看到的位置与选择。`lib/viewState.ts` 提供两个钩子,值都只是界面状态,不是数据:记住的值已经不适用(轮次、单位、日期、赛事被删)时页面忽略它,退回默认值。

- `useViewState(key, initial, lasting?)`:像 `useState`,值按键保存在内存里,应用运行期间有效;`lasting` 另存 `localStorage`,重启后仍在,只用于少数偏好式的选择,读回后页面再校验取值范围。`Set` 按数组存、按 `Set` 读回。
- `useScrollMemory(ref, key)`:记住滚动容器的位置,容器再出现时恢复。内容通常晚于容器到达,所以随内容变化重试,直到到达目标、用户滚动 / 点击 / 按键,或 1.5 秒为止。`StPage` 与 `StTable` 的 `scrollKey` 即用它。

记住的内容:

| 位置 | 内容 | 范围 |
|---|---|---|
| 赛事 | 上次所在的赛事页面(总览 / 项目 / 日程…),从赛事列表再进入时回到那里,没有记录时打开总览 | 运行期间,按赛事 |
| 项目工作区 | 所选轮次,编排与成绩共用;报名表、编排名单与组、成绩区的滚动位置(按轮次);上次所在的 Tab,从项目列表进入时用 | 运行期间,按项目 |
| 报名 | 树上选中的组别或单位、窄窗口显示树还是名单、树与名单各自的滚动位置、搜索词 | 运行期间,按赛事 |
| 项目 | 类型与组别筛选 | 运行期间,按赛事 |
| 项目、赛事设置、日程、赛事列表 | 滚动位置;全能工作区的 Tab | 运行期间 |
| 团体总分 | 项目性别、组别与页面滚动位置 | 运行期间，按赛事 |
| 日程 | 「未安排时间」展开与否 | 重启后保留 |
| 打印 | 报表种类与「比例」 | 重启后保留 |
| 打印 | 取消勾选的项目 / 轮次、日期、勾选的打印组别、侧栏滚动位置 | 运行期间,按赛事 |
| 设置 | 从工具栏打开(未指定分类)时宽窗口显示上次的分类;各分类内容区的滚动位置;操作日志的筛选 | 运行期间 |

编排页草稿、成绩页未保存的输入、对话框里的输入不在此列:它们有自己的离开确认,记住会让用户以为已经保存。

## 项目创建与配置

- `features/events/EventDialog.tsx` 的「常用项目」读取 Go 的 35 个预设，仅创建时提供；选择后带出项目名、类型、起跑方式、跳跃 / 投掷或建议棒数，可继续编辑。性别通常保留当前选择，混合接力预设选择「混合」。编辑已保存项目读取实际配置，不套用预设。
- 项目名称预览、配置显示规则、接力名单人数提示均经 `events/controller.ts` 调用 Go；自动编排与草稿保存经 `arrange/controller.ts`。不分道时道数输入置灰，已有值保留。
- `EventMeasurementFields.tsx` 共用项目配置控件，`form.ts` 保存表单初始值；计次、计分提供精度、排名方向、单次／取最好／求和，普通队伍提供建议人数。
- 「赛制」下拉与各轮次的晋级人数由 `events/format.ts` 的纯函数组织(可选组合、切换组合时保留仍在的轮次的人数),表单里的 `rounds` 原样交给 Go 校验;项目列表的「赛制」列显示 Go 的 `formatText`。
- 「项目」页(`features/events/EventsPage.tsx`)一张表列出普通项目与全能(分项不单列),有两种以上时可按类型(个人 / 队伍 / 全能)筛选;「添加全能」与「添加项目」并列在工具栏,编辑与删除按行的类型打开对应对话框。`features/combined/` 提供创建／编辑、全能工作区、统一报名、总成绩、计分表预览与规则重算，完整规则见 [combined.md](combined.md)。
- 成绩页位置名称和逐次表头来自 `EventDetail.rules`；投掷显示「试投」，支持 `X`、`-` 与「免投」。

## 报名限制

- 「赛事设置」的「报名限制」与赛事列表「编辑」打开的 `MeetDialog` 共用 `MeetLimitFields`;三个限报输入框只保留两位数字,空为不限(`meets/limits.ts`,有单测);范围校验在 Go。
- 报名对话框(`AddEntriesDialog`、`AddTeamsDialog`、`CombinedEntriesDialog`)随勾选经 controller 的 `useEntryLimitWarnings` / `useCombinedLimitWarnings` 调用 Go,由 `event/LimitNotice.tsx` 显示前 3 条与剩余条数,不禁用「报名」。钩子按 ID 内容而不是数组对象触发请求:对话框关着时每次渲染都会传入新的空数组,按对象触发会无限重渲染。
- 报名表在姓名旁标「超出限报项数」「单位超出限报」,运动员列表的报名项数用警告色;表格导入预览的「说明」列原样显示 Go 写的提示。计数规则见 [domain.md](domain.md)「报名限制」。

## 队伍与接力

- 项目可按个人或队伍参赛，接力固定按队伍参赛。报名页与编排名单底部的「管理队伍」打开 `features/event/AddTeamsDialog.tsx`,显示队伍、单位、成员／棒次、报名状态以及编辑 / 删除入口;队伍经勾选后批量报名。
- `TeamDialog.tsx` 编辑队名、参赛单位与有序成员,提供增加、替换、上移 / 下移、移除棒次;已在同项目其他队伍的成员不列入候选。已有比赛记录时禁用名单编辑,保存失败保留输入,人数与性别警告由 Go 返回。所有读写经数据钩子和 `EventsController`,成功通过 `teams` / `entries` 事件刷新。
- 编排、成绩和报名表统一以 Go 返回的 `competitorId` 索引个人或队伍;接力使用道次和计时输入,报名数量使用「队」。业务约束见 [domain.md](domain.md)「队伍与接力」。

## 成绩页

- 每组的输入是本地状态,按组保存。项目详情重新读取时(本组或别的组保存、MCP 写入、运动员资料变化),`features/results/rows.ts` 的 `mergeRows` 逐位置合并:用户改过的行保留输入,其余行跟随新数据;整组直接换成新数据会清掉另一组里没保存的输入。
- 位置上换了人,该位置的输入丢弃,避免把成绩记到另一个人名下。刚保存的行跟随新数据,显示 Go 整理后的成绩文本,保存后该组不再算有改动。
- 成绩输入根据 Go 的 `rules.multipleAttempts` 和 `rules.markLabel` 显示单值或逐次记录；`StMarkField` 经 `lib/marks.ts` 携带完整项目配置调用 Go，计分小数位不在前端推断。
- 「放弃」恢复为已读取的数据,并去掉未保存的新增高度。读写经 `results/controller.ts`。
- `HeightResults.tsx` 提供高度专用表格：试跳格平时只读，按 `O` / `X` / `-`(及 `0`、`×`、`—`)记一次，光标留在本格(用户要求：照纸质记录逐人补录时自动跳转会打乱节奏);`Backspace` / `Delete` 撤销本格最后一次，方向键在可编辑格间移动并跳过弃权等禁用行。`Enter`、`F2` 或双击进入文本编辑可键入完整记录，`Enter` / `Esc` / 离开格子退出。「成功 O / 失败 X / 免跳 - / 撤销一次」按钮只出现在当前行、紧跟最后一个高度列，与按键同效；按下时不夺走试跳格焦点，点完仍可直接按键。
- 下一次记录要用本格的新预览判断可用性，预览返回前连续按下的符号排队，按顺序记到同一格，不会丢键。表头的新增高度框以 Go 的 `nextHeight`(重复上次升幅，只有一个高度时加 5 cm)作占位，空框按 `Enter` 或点「+」即添加该高度；添加后光标移到 `next`,预览返回前用户已点击表格或用方向键 / `Enter` 换格则不再移动。
- 每格按 Go 返回的 `state` 显示:`open` 待跳、`done` 已完成、`skipped` / `out` 底色变淡、`off` 禁用;`next` 只用于添加高度后定位光标，格子不另加标记。`StTrialsField` 是文本输入，无占位试跳符号，只以红框标出错误；错误文字由该行下方统一显示一次(从第一个高度列起),经 `aria-describedby` 关联到出错的格，窄格里不另写文字。`useHeightPreview` 调用 Go 预览，过期响应不覆盖当前输入；新预览返回前表格沿用上一次预览显示格子状态、当前最好与名次，记录、撤销与保存只认与当前输入一致的预览，否则每次按键都会让这些内容清空再出现；预览返回前点「保存」/「结束录入」先显示加载，等预览到达再提交。错误留在相应格或行，校验未完成与失败时禁止保存。保存期间试跳格只读而不禁用：禁用会夺走焦点、整组变灰一下。符号规范化、动作可用性、试跳顺序、最好成绩与组内暂定名次均来自 Go。
- 高度表头以米显示，点击弹出「修改高度 / 移除高度」菜单；修改保留整列记录，移除有记录的列先确认，修改 / 移除到保存后才写库。「放弃」恢复全部列与记录；空高度列、待添加高度文本也参与离开确认，空列本身不写入成绩。`height.ts` 合并已保存高度、额外列与有输入的草稿，外部刷新删去的高度仍保留草稿列，位置换人时不复用输入。
- 状态(弃权 / 犯规取消 / 无成绩)从行末「⋯」菜单设置或清除，设置后以标签显示在姓名旁；没有状态时不占列。
- 高度表格的顺序与姓名 / 号码 / 单位列固定在左侧，「当前最好 / 名次 / ⋯」固定在右侧，表头吸顶，内容在表内滚动；固定格在不透明底色上叠加行的悬停 / 聚焦色，与整行一致。上方信息栏显示当前运动员、高度、第几次与当前最好成绩。列模板只含固定宽度，没有高度时省去高度列段:`repeat(0, …)` 是无效值，会让整条模板失效、表格塌成一列。窄窗口控件换行，保持同一组件和输入焦点。
- 高度每组底部提供「放弃 / 结束录入 / 保存」；「保存」仅保存改过的行，「结束录入」确认后一次提交本组所有行，失败保留输入。过程记录显示「录入中」与暂定名次，全部位置确认后显示「已结束」。完成状态与晋级规则见 [domain.md](domain.md)「成绩」。
- 轮次排名有并列时,排名标题右侧显示「裁定并列」,有并列让本轮多出晋级名额时另显示「多 N 人晋级」标签。`results/TieDialog.tsx` 在一张表里列出各处并列(共享名次、姓名、单位、组、成绩),每人选「第 N 名」,同名次即保持并列;只提交有改动的整组并列(`results/ties.ts` 的纯函数,有单测),经 `ResultsController.ruleTies` 写入,名次与 `Q` / `q` 由 `results` 事件重读。规则见 [domain.md](domain.md)「并列裁定」。
- 所选轮次与编排页共用(见「视图状态」)。成绩页按需挂载访问过的轮次，切换时隐藏已访问轮次而不卸载；各轮次草稿与变更事件合并继续保留，任一轮次有修改时离开项目统一确认。当前轮次有草稿时显示「录入中」，下方排名明确标为「已保存排名」。
- 每组的列表一行一个位置(`.result-row`),各行用同一份只含固定宽度与 `fr` 的列模板(`--result-cols`),列才对得齐;列宽不够时整表横向滚动。有未保存改动的行,位置序号用强调色;状态为「正常」时下拉框文字用次要色,其余状态的行姓名变淡。
- 组标题经 `features/event/HeatTime.tsx` 显示生效时间 `scheduledText`:单独指定的用 `StTag`,沿用轮次(`scheduleInherited`)的用次要文字;其后经 `features/event/HeatStarted.tsx` 显示「开赛 `startedText`」与差值标签 `startDeltaText`,窄窗口下换到第二行;组内有成绩时,操作区左侧显示「修改于」与 `resultsUpdatedText`。
- 操作区的「开赛时间」图标按钮打开 `results/StartedDialog.tsx`(日期 + 时间):已有开赛时间时填入它并提供「清除」;没有时日期取生效计划日期,再取 `EventDetail.day`,时间留空(`results/started.ts` 的纯函数,有单测)。保存与清除经 `ResultsController.setStarted`(`Results.setStarted`)立即写入,成功后由 `heats` 事件重读。规则见 [domain.md](domain.md)「时间」。

## 编排页时间

- 组卡片与成绩页共用 `HeatTime` 显示草稿里的 `scheduledText` / `scheduleInherited`,另显示 `durationText`。草稿轮次带 `startAt` / `startText`,新组与没有单独时间的组按它显示沿用的时间,不在前端拼时间文本。
- 「编辑组…」以已有日期、轮次开始日期或 `EventDetail.day` 作默认日期,确定时经 `ArrangeController.heatPlan` 由 Go 校验时间与预计用时(输入原文传给 Go)并取回显示文本,一并写进草稿;校验失败留在对话框。
- 轮次开始时间经 `RoundStartDialog` 与 `ArrangeController.setRoundStart` 立即写入;两个时间对话框经 `useScheduleWarning`(调用 `Arrange.scheduleWarning`)在保存前显示 Go 给出的提示。
- `features/arrange/ScheduleDialog.tsx` 经 `scheduleController.ts` 调用生成的 `Arrange.previewSchedule` / `Arrange.schedule` 绑定,与 MCP 共用 Go 预览和提交。它接收轮次选项 `ScheduleOption[]`:编排页传当前轮次(单轮次请求),日程页以 `multi` 传全部轮次(多轮次请求,可勾选、调整先后、填轮次间隔;顺序的增删与移动是 `scheduleOrder.ts` 的纯函数,有单测);`version` 传读取选项的数据对象,它变化即清除预览。入口与草稿限制见 [arrange.md](arrange.md)「批量排时间」。
- 编排页组卡片的冲突标签经 `controller.ts` 的 `useDraftConflicts` 读取:草稿经 `draft.ts` 的 `draftTimes`(纯函数,有单测)转成请求,草稿变化与赛事数据 / 设置变化停顿 300ms 后合并为一次 `Arrange.draftConflicts` 调用,标签按组键对应。冲突列表(日程页与连排预览)共用 `arrange/ConflictList.tsx`。
- 请求期间禁用日期、时间、间隔与取消操作;过期预览或提交失败后保留输入,清除确认状态并要求重新预览。保存成功经 `heats` 事件重读,页面不自行改时间。

## 总览

赛事的第一页,看全场走到哪一步、接下来比什么。数据来自 `service.Overview`,读一次 `loadMeetPlan` 与报名进度,查询次数固定;各阶段的判定都在 Go,页面只排版。

- **工作流**:按「赛前」「比赛」「赛后」三段排列,段内是步骤卡,序号跨段连续;点卡片进入对应页面(编排、成绩与晋级进「项目」)。每张卡写「完成数 / 总数」与它数的是什么,下面是 `StProgress` 进度条(只计数的步骤没有),序号圈按状态着色:没开始灰、进行中蓝、全部完成绿并换成对勾。`Overview.current` 是第一个既没完成也没停用的步骤,这张卡描主色边框、写「下一步」,并带 `aria-current="step"`;「下一步」三个字对读屏隐藏,由 `aria-current` 表达。卡片宽度用 `auto-fill` 固定,步骤少的段与五步的段卡片一样宽。
  - 赛前:
    - 项目:个人与队伍项目数(不含全能分项),有全能时标「全能 N」;有项目或全能即完成。
    - 参赛单位:单位数,有单位即完成;赛事有组别时标出没有组别的单位「未分组 N」,点卡片进「报名」并选中树上的「未分组」。
    - 报名:有报名或队伍的单位 / 全部单位,超出报名限制标「超限 N」(同「报名」页)。
    - 编排:第一个轮次已有组的项目 / 有报名(或已有组)的项目,全能分项也算项目。
    - 日程:有计划时间的轮次 / 这些项目的全部轮次,运动员时间冲突标「冲突 N」。
  - 比赛:
    - 成绩:全部位置都有成绩的轮次 / 这些项目的全部轮次;高度项目只保存了过程(未「结束录入」)不算有成绩。有成绩但没完成的标「进行中 N」,只要有轮次开始录成绩,步骤就是进行中。
    - 晋级:只在有预赛、次赛或半决赛时出现。下一轮次已有组的轮次 / 要晋级的轮次;已完成、下一轮次还没有组的标「待晋级 N」,其中只能由裁判裁定、影响晋级人数的并列标「待裁定 N」。成绩之外只为这些轮次的项目再读一次完整成绩,查询次数固定。
  - 赛后:团体总分:没启用时写「未启用」,不算下一步,点卡片进「团体总分」页启用;启用后是已完成的计分项目 / 有报名、倍数大于 0 的项目与全能,项目看决赛,全能看全部分项的决赛。
  - 每段标题右侧是这一段要打印的报表,点击进「打印」并选好该报表(写入 `reports/kinds.ts` 的 `reportKindKey`):赛前「报名表」「秩序册」,比赛「检录单」「成绩记录表」,赛后「成绩册」与启用后的「团体总分」。
- **待比赛**:有计划时间、还没完成的轮次按时间排列,最多 6 个;时间是赛事第一天的只写时刻。每行写项目与轮次、时间与组数(没有组写「未编排」),已有成绩的标「进行中」;点击进入该项目的成绩(没有组时进编排)。超过 6 个时标题右侧「全部 N 个」进日程页。
- **赛事结构**(`overview/StructureMap.tsx`):工作流下方的思维导图,赛事 → 组别 → 参赛单位 / 项目,数据是 `Overview.structure`。没有组别时参赛单位与项目直接挂在赛事下;有组别时末尾的「未分组」只在有未分组的单位、运动员或项目时出现。单位写人数与「未报名」「超限 N」,项目按状态着色(未编排灰、已编排蓝、进行中橙、已完成绿,同「项目」页的进度标签),状态写在悬停提示与无障碍名称里。每个分支最多显示 8 个,其余写「+N」。点击跳转:赛事进「报名」的「全部」,组别与「参赛单位」进「报名」并选中该组别,单位进「报名」并选中该单位,「项目」与「+N」进「项目」页并筛选到该组别,项目进它的工作区(未编排进报名、已编排进编排、其余进成绩),全能进全能工作区。连线由列表的边框画出,不量尺寸;窄于 1000 时改为自上而下的缩进排列。
- **赛事**:日期、地点、参赛单位数、运动员数、组别数(没有组别不显示)与报名限制(都为 0 写「不限」)。
- 宽窗口下待比赛与赛事左右并排,窄于 1100 时上下排列;步骤卡按宽度自动换行。

## 设置页

- `src/features/settings/` 按主题分类(通用 / 编排 / 打印 / MCP / 操作日志 / 关于),每类一页;宽窗口左侧常驻分类列表,窄窗口分两级。
- 宽窄切换只增减左侧分类列表,内容区留在同一树位置,表单、焦点与未保存修改都保留。
- 开关与分段控件立即生效;需要保存的表单经底部保存栏,有修改时离开先确认。
- 偏好(通用 / 编排 / 打印)点下即显示新值,保存依次发出,每次都带上至今的全部改动;重新读取的设置带上该值之前一直显示所选值,保存失败则退回。保存期间不置灰控件:每点一下整块面板都会闪一次。

- 通用:外观(跟随系统 / 浅色 / 深色),经根元素 `data-theme` 应用。编排:同单位分散、均衡人数,作为自动编排对话框每次打开时的默认值;「时间冲突」的最短休息时间(`StSelect`:只查重叠 / 5–60 分钟,选择即生效),冲突检查经 service 读取;「检录」的检录提前时间(`StSelect`:不显示 / 10–240 分钟,默认 20)。分钟选项由 `settings/minutes.ts` 生成,已存的值不在列表里时追加显示(有单测)。打印:秩序册是否印代表队名单与竞赛日程表、成绩册是否印「团体总分表」（默认开）与「成绩时间」、检录单与成绩记录表各自的「分页」(`StSelect`:不分页 / 每个轮次一页 / 每组一页,默认每个轮次一页)、每个项目另起一页,Go 生成预览与打印 HTML 时读取同一设置。
- 操作日志:只读表格,按赛事(`StSelect`)与来源(`StSegmented`:全部 / 界面 / MCP / 系统)筛选,每页 50 条,「加载更多」接续上一页,没有更多时置灰。任一数据变化重读最新一页并与已加载的页按 id 合并(`settings/auditLog.ts`,有单测);新记录多于一页、接不上已加载部分时从最新一页重新开始,不显示断档。读取经 `settings/controller.ts` 的 `useAuditLog` 与生成的 `Settings.auditLog`。
- MCP:本机开关、运行状态、端口、令牌显示 / 复制 / 轮换与复制连接信息。端口单独编辑保存,失败保留输入;有端口草稿时禁用开关与轮换,避免隐式提交草稿。关于包含版本、GitHub 仓库、软件更新与开源许可；仓库经 `bind.App.OpenRepository` 用系统浏览器打开，链接地址由 `App.Info` 返回。
- 新版本检测用 mygo 的更新插件(`main.go` 里 `mygo.Use`),窗口固定简体中文:启动 10 秒后与每天各在后台检查一次,有新版本时弹出更新窗口,可安装、稍后提醒或跳过；「检查更新」经 `bind.App.CheckForUpdates` 立即打开同一窗口。`App.Info` 返回当前构建能否自行更新及说明；开发运行与无法自行更新的安装方式不做后台检查，关于页显示「手动更新」与「查看发布」，经同一绑定用系统浏览器打开仓库的 `/releases`，供用户选择版本下载安装。
- 「接收测试版」默认关，保存在 `Preferences.updatePrereleases`，与其余偏好共用 service 写入、日志与事件。启动读取及每次设置写入成功后，主程序在广播事件前通过 `mygo.Updater.SetPrereleases` 应用选择；开启时检查正式版与测试版中的最新版本，关闭后等待高于当前版本的正式版，不降级。关于页与其他偏好共用 `settings/controller.ts` 的 `useOptimisticPreferences`，点击「检查更新」等待已排队的保存完成，保证立即检查使用保存后的渠道。
- 赛事列表工具栏与赛事侧栏均提供设置入口,返回恢复进入设置前的页面。分类导航经同一 `useNav` 离开确认,宽窄变化只通过 CSS 控制分类列表的可见性。
- 读取经 `settings/controller.ts` 的钩子,写入经 `SettingsController` 与生成的 `Settings` 绑定。普通偏好与 MCP 配置分开读取,普通偏好接口不含令牌。设置写入广播 `kind=settings`,外观与打印预览按事件刷新。

## 打印

- 打印选择项由 `Reports.targets` 提供普通项目和全能，秩序册与成绩册选择全能展开全部分项与汇总表，报名表只列统一名单；读取、生成与打印经 `reports/controller.ts`。
- 报表种类经 `StSelect` 选择，选择跨页面与重启保留。
- **报名表**（`Reports.render("entries", …)`，service `renderEntries`）：按项目选择范围，普通项目按项目列表顺序，全能在其后；每项按报名顺序列序号、号码、姓名、单位，有报名成绩时增加该栏，标题写人数或队数。名单只读报名，与编排及晋级无关；队伍按有序成员显示号码与姓名，全能只印统一报名名单，分项不重复列出。没有报名的项目显示「还没有报名」，沿用「每个项目另起一页」、续页提示、页眉、页码与打印时间。
- 秩序册按起跑方式显示「道次」或「顺序」。项目标题右侧一行写日子(带星期)与起跑方式或尝试配置;秩序册的组标题右侧写时间与人数(队伍项目写队数)。
- **版式**:看的表(报名表、秩序册、成绩册、团体总分)只留横线:表头上下与表尾粗线、行间细线,不画竖线和灰底;手写的表(检录单、成绩记录表,`.grid`)全框线、格子加高、号码加粗加大。字号用 pt,不随 WebView 的像素换算变化。姓名一栏吸收余下的宽度,其余栏按内容定宽;半页宽的组(`.heats` 两栏)单元格不换行、单位栏按文字收窄。
- **只印有内容的栏**:秩序册整个项目都没有报名成绩时不印「报名成绩」;队伍项目不印「号码」栏(号码随队员写);排名表只有一组时不印「组」。队伍名对读者没有信息时不印:同一项目所有队伍同名,或队名就是参赛单位的全称 / 简称(`printedTeamNames`),表头随之写「棒次」/「成员」而不是「队伍 / 棒次」;报名表、秩序册、成绩册、检录单与成绩记录表同一规则。
- **队员**:队伍项目的队员连同号码写在队名下面(「1棒 周书航 12101」);报名表、秩序册、成绩册里一行排开、按人换行,队伍项目的组整行排(`.wide`);检录单与成绩记录表每人一行,便于逐个点名。
- **成绩册的逐次成绩**:多次尝试的项目每次一栏(「第1次」…,按尝试次数,有人多出时补栏),算作成绩的那一次加粗(取最好的项目;求和不标),放在「成绩」之前;有逐次成绩的组整行排。高度项目印「试跳记录」:逐个高度写高度与试跳格(「1.55 XO」)。
- 项目按项目列表的顺序排列;组的时间与项目同日只印时刻;两类报表末尾印「打印时间」(见 [domain.md](domain.md)「时间」)。秩序册开头的「竞赛日程表」见 [domain.md](domain.md)「时间」;每个项目另起一页时,日程表之后的第一个项目也另起一页。
- **代表队名单**:秩序册在竞赛日程表之前印「代表队名单」(「设置 → 打印」可关,默认开;service `rosterBook`),成绩册不印。
  - 每个参赛单位一段:全称、人数与号码范围(按号码排序后的第一个与最后一个,如「11101–11208」,发号码布时核对),下面按「男子」「女子」「其他」(未填性别)分开、各带人数,每行 4 人,印号码与姓名;一个单位只有未填性别的人时不印性别标题。组内表格里的单位用简称,名单用全称,读者从这里对上两者。
  - 顺序:参赛单位按参赛单位列表的顺序,没有参赛单位的运动员归在最后的「无参赛单位」;运动员按号码排(`bibLess`:数字按数值,其他文字在数字之后,没有号码的在最后,相同时保持录入顺序)。
  - 范围:打印全部项目时列出赛事的全部运动员,没报名的也在;只选部分项目时只列在这些项目里报名的运动员,队伍展开为队员,选全能即含全能的报名者。没有可列的人的单位不印,一个人都没有就整节不印。
  - 一个单位能放进一页就不拆开(`.unit`,预览的分页器同样处理);每个项目另起一页时,名单与日程表接着排,其后的第一个项目另起一页。
- 报名表、秩序册、成绩册、检录单、成绩记录表由 Go `internal/report/` 生成完整 HTML 文档(号码布待实现)。「打印」页在 `iframe` 里把它排到 A4 纸面上预览(见下条)。
- **打印的是预览排好的纸面**:点「打印」时 `paginate.ts` 的 `printable` 把显示中的纸面连同样式序列化(比例与预览底色去掉),经 `Reports.printPages` 交给 Go 另开窗口载入并调出系统打印对话框(可另存为 PDF)。每张纸是一页:`paginate` 往文档里加 `@page { margin: 0 }`,边距在纸面自身的内边距里;打印媒体下纸面去掉阴影与间隔、每张后换页,高度比 A4 短 1mm,免得取整把一张纸挤成两页。不打印 Go 的连续文档:那样由 WebView 自己分页,换页提示与页码印不出来,分页也和预览不一样。预览换成新报表之前「打印」置灰,免得印出上一份。不在主窗口里打印:主窗口的页面是应用界面,打出来会带上侧栏。
- **预览按纸张分页**:`reports/ReportPreview.tsx` 把 Go 的 HTML 载入 `sandbox="allow-same-origin"` 的 `iframe`(不放行脚本,只让页面能读写它的文档),载入后由 `reports/paginate.ts` 把内容搬到 A4 纸面上,预览上方显示页数与「比例」(`StSelect`:适合宽度 / 50%–150%,默认适合宽度,随窗口宽度重算)。Go 的报表是一份连续的文档,直接显示看不出每页印什么。
  - 分页规则:放不下的容器(`section` / `div` / `table` / `tbody`)在下一页接着排,表格重复表头;`.heat` / `.sheet` / `.line` / `.unit` 能放进一页就不拆;标题与表头不单独留在页尾,也不算作页面内容;强制换页读元素的 `break-before` 计算值,所以 Go 把「另起一页」写成不限打印媒体的规则。纸面尺寸与边距(`.pv-*`)写在 `internal/report/style.css` 里 `@page` 旁边,改纸张时两处一起改。
  - **换页提示**:只在表格从行之间断开时加:上一页紧贴表格最后一行下方左侧印「续下页」(按断开时测得的表格底边定位),下一页表格接着的部分上方印它接着的标题加「（续）」,如「男子100m 初一组 · 决赛（续）」。轮次、组、参赛单位这类从自己的标题开始的块换页时不加:标题已经说明它是什么,再加一行就是重复。标题取跨页的各层容器(外到内)在断开处之前各级(h2 / h3 / h4)的最后一个标题,只取标题本身的文字(不含 `<small>`),成绩册的组别标题不取(项目名已带组别),纯函数 `continuedTitle` 有单测。表格只剩表头时连同标题挪到下一页,不算断开;强制换页(另起一页)不加提示。
  - 分页在已连接的报表子树中一次测量位置，按测量结果批量放入表格行与组，再用实际溢出校验；大型嵌套容器直接拆开，避免反复排版整个子树。约 8ms 工作预算后在批次间让出主线程，单次浏览器布局仍可能超过预算；报表切换与离开页面会取消在途分页，过期结果不更新页数。
  - 没有可预览的内容时不显示空白的预览,用 `StEmpty` 说明原因(还没有项目 / 还没有组 / 当天没有组 / 未选择项目 / 未选择轮次),此时「打印」置灰;读取失败显示错误。
  - **新报表在旧预览下面排好再替换**:新的 `iframe` 叠在旧预览下层(标题「下一份预览」),载入并分页完成后移除旧预览,它就成为显示的那份(标题「预览」),期间旧预览一直可见。直接替换会先闪出未分页的连续文档,再跳成纸面。分页出错也照样替换。连续切换时只保留显示的一份与最新的一份;第一份报表载入时由一块底色遮住。
  - **`iframe` 建成后不改样式,只靠建立时定下的层叠顺序(新的在下)**:不用 `pointer-events: none`、透明或隐藏来藏下层的那份。WebKit 有时在这类样式去掉后仍把该框当作不可滚动,滚轮落到整个窗口,预览滚不动。
  - 所有项目都勾选时请求不带项目(等于全部),包括取消勾选的项目后来被删除的情况;否则秩序册会把「打印全部项目」当作「只打印部分项目」,代表队名单少列没报名的人。
  - 每份报表用一个新的 `iframe`(以 HTML 为 `key`),不改已有 `iframe` 的 `srcdoc`;纸面四周的底色由页面按预览区的背景色写进 `iframe` 文档(主题变化时重写),不靠透明:报表文档是浅色方案,深色主题下透明的 `iframe` 会被 WebView 涂成白底。不改 `srcdoc` 是因为WKWebView 在同一个 `iframe` 的 `srcdoc` 短时间内连改两次时会丢掉第二次,预览停在空白。
- 检录单(`Reports.checkInTargets` / `renderCheckIn` / `printCheckIn`,service `RenderCheckIn`):「打印」页的「检录单」。侧栏上方「日期」(`StSelect`:全部日期 + 有计划组的日子)筛选,下方按轮次勾选(项目只有一个轮次时只写项目名);选了日期只列当天有组的轮次。全部勾选时请求不带轮次(等于全部),否则带勾选的轮次;选择逻辑是 `reports/checkin.ts` 的纯函数(有单测)。
  - 内容:每组一张,印赛事、项目、轮次、组、计划时间、检录时间(提前时间为 0 时整格不印)、道次 / 顺序、号码、姓名、单位与「到」「缺」方框,末尾「应到 N 人,实到 __ 人」与「检录员」签名;不是第一个轮次时标题右侧写「由预赛晋级」(前一个轮次)。队伍项目印队名与成员 / 棒次(含号码),人数写成队数。没有计划时间的组照印,时间留空。
  - 顺序:不选日期时按项目列表顺序、轮次、组序号;选了日期只印当天的组,按生效计划时间排。分页按「设置 → 打印 → 检录单 → 分页」(service `sheetBreaks`):每个轮次一页(默认)时同一轮次的各组接着排在同一张纸上,排满才换页,轮次变了另起一页,按日期打印时相邻两组轮次不同也另起;每组一页时每张另起;不分页时只在排满时换页。一组能放进一页就不拆开。已保存的设置里旧的「每组另起一页」开关打开时读作每组一页。
- 成绩记录表(`Reports.renderRecordSheet` / `printRecordSheet`,service `RenderRecordSheet`):「打印」页的「成绩记录表」，场地裁判手写成绩用。选择方式、请求(`CheckInRequest`)与顺序同检录单,按组选取与名单是 service 里两者共用的一段;分页同检录单,用自己的设置项。
  - 每张印赛事、项目、轮次、组、计划时间、待填的「实际开赛」、道次 / 顺序、号码、姓名(队伍印队名与成员 / 棒次)、单位,之后是待填的栏目、名次,末尾「应到 N 人,实到 __ 人」与「记录员」「裁判长」签名。只留空格:已录入的成绩不印,免得手写稿与系统里的数对不上时分不清哪个是现场记录。
  - 栏目只看项目类型与已保存的配置(`recordColumns`),不按项目名推断:径赛与接力填「成绩」,分道起跑的个人径赛另留整组「风速」;远度按尝试次数每次一列加「最好成绩」,跳跃每人多一行逐次「风速」,投掷没有;高度留 10 列,表头空着由裁判写高度(项目不保存起跳高度),加「最好成绩」;计次与计分填「次数」/「分数」,多次尝试时前面按尝试次数每次一列。
- 打印 HTML 同样数字等宽(`font-variant-numeric: tabular-nums`)、同样遵守文案规范。
