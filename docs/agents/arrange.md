# 编排页

前端 `src/features/arrange/`,规则在 Go `internal/arrange/` 与 `internal/service/`。层级与锁定口径见 [domain.md](domain.md)。

## 页面

- 接力的名单与位置表示队伍,与个人项目共用草稿移动、保存、排道、计划时间和晋级逻辑;「管理队伍」可编辑队名、单位和棒次并报名。队伍规则见 [domain.md](domain.md)「接力」。
- 一个项目一页,标题旁可切到同一赛事的其他项目;左栏是本项目报名者名单(窄窗口收为侧面板),右侧是各轮次的组卡片。
- 多轮次项目在工具栏切换轮次,名单显示当前轮次里未分组的人。
- **拖放排位**:名单拖到位置,或点选后点「放到这里」;拖到有人的位置即互换(从名单拖来则原来的人回到名单),拖回名单即移出。径赛每组固定显示全部道次,田赛顺序始终连续(1…n)。组卡片「⋯」里编辑名称与计划时间、上移 / 下移、解锁位置、删除。
- 名单底部「从赛事添加」直接报名(可多选);取消报名与报名成绩在「报名」页;**报名立即生效,不进草稿**,之后把最新数据合并进草稿,未保存的排位改动保留。

## 本地草稿,一次保存

- 排位、组名与逐组计划时间改动进不可变草稿 `ArrangeDraft`,配合撤销 / 重做(上限 100 步):`Ctrl/Cmd+Z` 撤销,`Ctrl/Cmd+Shift+Z` 与 `Ctrl+Y` 重做,`Ctrl/Cmd+S` 保存,`Esc` 取消点选。
- 有未保存改动时离开页面先确认。
- 保存期间禁止继续编辑;绑定在写入后返回 service 重新读取的项目详情,界面以该快照确认草稿已保存,清除临时新增组、重置标记和历史。期间到达的数据事件暂缓合并,避免新增组同时保留临时键与数据库 ID;其他外部变更仍按下述指纹合并。保存失败保留草稿并重新读取以合并外部变化。
- 工具栏右对齐,「放弃」常驻(无改动时置灰),改动计数放在操作最左,改动前后按钮不移位。
- **保存只提交改过的组**:每个已有组带载入时的指纹 `base`(序号、名称、计划时间、位置;由 Go `arrange.Fingerprint` 计算,前端当不透明字符串比对),连同新增组、显式删除列表与本轮次全部组的显示顺序 `order` 一起提交;没提到的组只可能被改序号,或被移走已排到别组的人。
- 草稿是 `src/features/arrange/draft.ts` 里的纯函数(有 `bun test` 单测),只负责在位置间移动人;分组排道、序号、锁定判定都在 Go。
- **数据变化即合并**:MCP 在编排页打开期间也可能写入。service 广播变更后,草稿逐组对比 `base`:被改过的组换成最新内容(丢弃本地对它的改动),其余改动保留;丢弃了本地改动就提示「有组已在别处修改」。保存时指纹不符同样重新载入并合并,不弹冲突对话框。
- 组序号由 Go 在保存时按 `order` 派生(`arrange.DeriveOrdinals`):「原序号仍递增就保留,否则取前一个 + 1」,尽量少改。
- 合并后撤销 / 重做历史清空:历史里的草稿带着旧指纹,撤销回去会把别处的改动盖掉。

## 自动编排

- **只排未分组的人、只追加新组**,已有组不动。
- 选项:每组人数、排列顺序(按报名成绩 / 随机)、位置分配(径赛「好成绩排中间道」/ 依次 / 随机,田赛依次 / 随机)、同单位分散、均衡人数。按成绩时蛇形发牌,各组强弱相当;没有报名成绩的排最后。
- 上一轮有晋级规则时,人员可选「上一轮晋级者」:取上一轮带 `Q` / `q` 的人,以上一轮成绩为种子;上一轮没录完即拒绝。
- 由 Go `arrange` 计算方案,原样追加进草稿,保存前可随意再改。随机由前端生成 `seed` 传给 Go,同一 `seed` 结果相同,便于复现与测试。

## 批量排时间

- 编排页当前轮次的工具栏「⋯ → 批量排时间…」打开对话框;输入首组日期、首组时间与间隔,先「预览」,再「保存」。默认日期取首个未比赛组的现有日期、项目日期、赛事开始日期,时间取该组现有时间或 09:00,间隔默认 5 分钟。
- 该操作立即写入已保存的组,不进入排位草稿;存在任意未保存编排改动、正在保存或当前轮次没有已保存的组时入口置灰。有草稿时提示「请先保存编排」。这样可以避免批量时间写入后,草稿里同一组的排位或名称被合并覆盖。
- service `schedule.go` 的 `PreviewSchedule` / `ApplySchedule` 同时供界面绑定与 MCP 使用。前端 `ScheduleDialog` 经 `scheduleController.ts` 调用,不计算时间。预览列出实际变化的「原时间 → 新时间」与跳过的组;修改任一参数或接收项目数据变化后清除预览。
- 按组序号从小到大处理当前轮次。首个未比赛的组使用首组时间,之后每个未比赛的组递增间隔;有成绩的组由 `HeatFacts.KeepReason` 判定并跳过,不占间隔。未比赛组已有的计划时间参与重新安排,与目标时间相同的行不列入改动。
- 首组时间必须是有效的本地 `YYYY-MM-DDTHH:mm`,年份 1–9999,间隔为 1–1440 分钟的整数。按本地年月日时分运算,支持跨午夜、跨年与闰日,不转换时区或按夏令时跳时;超出日期范围时整批拒绝。
- 预览和提交均持 service 写锁读取。指纹覆盖参数、项目及目标轮次完整状态,包括组序号、名称、时间、位置与成绩。提交重新计算后比对指纹,不一致返回 `E_STALE`,要求重新预览;任一错误阻止整批写入。
- 保存仅在一批事务中更新变化组的 `scheduled_at`,不改组序号、位置、成绩、名次或晋级;日志动作 `heats.scheduled` 保留原时间和新时间,来源分别为 `ui` / `mcp`,成功广播 `heats` 后由界面重新读取。
- 空轮次、全部已比赛或时间完全相同时可预览但没有改动,界面「保存」置灰;确认提交空改动不写日志、不发通知。


## 已比赛的组

- 有成绩的组默认锁定:里面的人可以拖出来排进下一轮次的组,但仍留在原组;要从原组移出或改位置,须先「⋯ → 解锁位置…」。解锁后换位置,成绩跟着人走;移出的人成绩在保存时删除,该组名次重算。
- **全部重置**:「⋯ → 全部重置…」弹窗列出将删除的组与成绩数,必须输入项目名称才进入重置草稿;保存按钮变成红色「重置并保存」(`StConfirmButton`)。这是唯一能一次删掉已比赛组的入口。
